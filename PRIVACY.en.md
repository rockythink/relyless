## 2. How We Handle Data

### 2.1 Local-first, not fully offline

The Extension is local-first by default: local domain classification and on-device records do not require uploading entire pages to any server we operate; the Extension does **not** run a relay cloud service, and we do not operate any server that collects your reading content.

However, when you use AI assistance, the text needed for the task is sent to the model provider you select (for example, an API endpoint you configure, or the ChatGPT service reached through a native connector you install).

**Focused reading** locally extracts and rebuilds a snapshot of the current article only after you select the popup action. The snapshot exists only in the current page’s memory and is removed on exit, navigation, or page close; this adds no full-page upload, article storage, or URL record and does not require a model. Entering the view alone makes no model call. The “Translate page” control at its top requires a separate usage estimate and confirmation (and another confirmation if over budget); it sends only nearby snapshot text as you read. Exiting removes the displayed translation but cannot retract a sent, potentially billable request. Existing automatic English assistance, if enabled, and explicit lookup, explanation, or translation requests still send only the necessary text under the rules below. On-demand mode performs no passive analysis, prefetch, annotation, or recording in this view. Unreliable extraction refuses to open. Images may load from their original resource URLs; use the original page for media or unloaded images.
### 2.2 Content sent to your model provider

When you use AI assistance, the following is sent to your selected model provider:

- **Reading assistance**: target words/sentences plus applicable page title, section information, and context. In focused reading, holding the lookup key and clicking an English body word explicitly sends that word and limited context even if page-wide automatic assistance is off; it does not enable passive scanning. The same explicit action on other visible English can request help for words in links, sidebars, or control labels; only the clicked word and limited context from that label are sent (link text is capped at 200 characters). Input fields, editable content, and hidden text are excluded. Navigation and controls are never scanned or sent automatically. Automatically prepared article context is at most 12,000 characters; a short article may be included in full. Requests also contain task instructions and structured-output constraints.
- **Remote domain detection** (if you select a non-local mode): a title and a length-limited body sample are sent to the detection channel you choose — the ChatGPT, Grok, or Google subscription connector or your configured detection API; in Jev judgment mode, to the judgment endpoint you configure (Requesty or SiliconFlow System One). The default local domain detection does not produce this remote request.
- **Model-routing judgment** (if you explicitly enable model routing): a bounded request summary of at most 2,000 characters — target words or context — is sent to the configured judgment endpoint to decide whether to escalate; the decision is cached only on-device and incognito windows keep no such cache.
- **Manual selection or navigation-link translation**: only after clicking the selection action, holding the lookup key and clicking a navigation link, or using its context-menu action is the selected body text or that link’s text sent (navigation text is capped at 200 characters); a body-text selection may include limited context. Navigation is never scanned or sent automatically. The translated label appears beside the original link text without replacing the link.
- **Bilingual page translation**: only after confirmation in the popup or focused reader, nearby body text (the local snapshot while in focused reading) and limited context are sent — title and current section up to 160 characters each, adjacent body text up to 400 characters before and after; at most four items per batch, source text up to 4,000 characters in total, and source-plus-context up to 12,000 characters. Input fields, hidden body text, and video captions are not read.
- **Assistance and translation inside the PDF reader**: the built-in PDF reader parses and lays out the document with a locally bundled PDF.js. Clicking a word, translating a selection, or running block/page translation sends the selected text and its containing block under the same rules as the corresponding web actions above. The PDF address is used only to fetch the file on your device and is never sent with model requests; document content is never scanned or translated automatically. When a remote PDF host does not allow cross-origin reads, the reader shows a button and only requests site access after you explicitly click it; declining grants nothing and affects no other site.
- **Reading summaries** (if you explicitly enable): length-limited reading samples.
- **Personalization analysis** (if you further enable): limited queries, example sentences, summaries, and objective activity statistics from the last 30 days.

**About the "On-device model" channel**: when you select "On-device model (Gemini Nano)" as the provider, valid short word/phrase hints are generated by Chrome's built-in model on your device and **no text is sent to any server**. If the local call fails or returns invalid content, short hints also fall back to a configured ready API service or an authenticated subscription. Batch assistance, page translation, follow-up questions, and other requests likewise fall back; text in these fallback requests is sent per the table above. When no fallback service is available, the request fails with an explicit error rather than silently sending data.

Request payloads do not actively include the page URL, but providers still receive normal network request metadata and may record requests, accounts, and content under their own terms. **We cannot guarantee that a third-party or self-hosted API endpoint does not retain data.** Review your provider's privacy and retention policies before use.

### 2.3 What is stored on-device

- **API keys and service configuration**: stored in your browser's local extension storage, used to authenticate to the corresponding endpoint.
- **ChatGPT SIWC credentials**: OAuth access/refresh tokens, the host ID, issued client registrations and account mappings are managed only by the local Node Native Messaging host in its data directory’s `siwc.json` (POSIX mode 0600; Windows access control depends on the OS account and directory permissions). Codex CLI credentials are not imported. Credentials never enter extension storage, webpages, diagnostics, or exports. The extension receives only the sign-in entry point, account status, and model information.
- **Grok OAuth credentials**: access tokens, rotating refresh tokens, and account records are held only by the local Node Native host in its data directory’s `grok-oauth.json`, with atomic refresh-record replacement (POSIX mode 0600; Windows access control depends on the OS account and directory permissions). Old Grok CLI credentials are not imported. Credentials never enter extension storage, webpages, diagnostics, or exports. The browser receives only a trusted verification URL, a short user code, and sanitized account/model status.
- **Runtime diagnostics (enabled by default)**: structured metadata stays on-device, such as timestamps, operations, random request correlation IDs, provider channels, stages, status, duration, error codes, HTTP status, bounded length/shape counts, and provider/model fingerprints. It contains no source text, full model responses, URLs, keys, OAuth credentials, or account information and is not automatically uploaded. Extension storage keeps up to 500 records and prunes records outside a seven-day window on reads/writes. The Native host (including Grok) stores `diagnostics.jsonl` and one rotated file, each up to 256 KiB; records older than seven days are removed at host startup, not erased at an exact expiry time. The extension skips incognito-request diagnostics, but the host may still retain request metadata without content or account information.
- **Personal vocabulary profile**: on by default, used to remember requested words and support preferences. It stores short sense labels and numeric vectors generated on-device when the local model is already warm; it does not store source sentences, titles, or source URLs. Older senses without vectors are compared by computing temporary vectors only when needed and the model is warm. You can disable it in settings (after which it is no longer read or updated) or clear it under "Data & Privacy."
- **Reading history** (off by default; requires explicit opt-in and a list of allowed sites): stores queried terms, length-capped example sentences with their translations/explanations, reading summaries, and objective daily active-time, visible-word, and help-request statistics. Collection runs only in automatic assistance mode; scrolling and hover do not infer completion or ability. Example sentences are capped at 1,000 characters (longer sentences are not stored), per-item translations at 2,000 characters, explanations at 1,200, and sentences in automatic-annotation events at 2,000. At most 300 events are kept for up to 90 days, without source URLs. You can export or clear them under "Reading history" or "Data & Privacy."
- **Model usage statistics**: after model calls, local extension storage aggregates request and error counts and provider-reported input/output tokens by date, service name, model ID, and operation. Missing token counts are estimated separately from request/response character lengths, not presented as exact billing. Up to 90 days and 400 aggregate rows are retained. Request text, page URLs, and keys are not stored in these statistics; incognito model calls are excluded. You can clear them independently under “Model usage” or together with “Clear all reading data.” Turning off reading history does not automatically delete existing usage statistics.
- **Prepared explanations and limited context cache**: kept only for the current browser session.
- **Temporary ChatGPT host conversations**: bounded question/answer history stays only in Native host memory, expires after 30 minutes of inactivity, and is limited to 50 conversations and the latest 12 question/answer pairs per conversation. It is cleared on sign-out, account changes, or host exit and is not written to host disk. Each model request resends the required limited history.
- **Explicit follow-up records**: limited selected text, context, questions/answers, the page title, and a page address with query parameters and fragments removed are stored in local extension IndexedDB for up to 30 days and 40 turns per conversation so you can continue your questions. Incognito windows do not persist them. These records are separate from temporary host conversations and opt-in reading history; delete them under “Reading history → Conversations.” Reading-history exports do not include them. Continuing a conversation sends the required limited completed turns; these can rebuild context after the host restarts.
- **Documentation-site hint settings**: your hint keyword list and the origins of sites where you chose “Don't hint again” are stored in local extension settings (at most 500 entries; the oldest is evicted when full); full browsing URLs are not stored. Incognito dismissals store only the site origin in extension session storage, separate from regular windows, and are removed when the last incognito window closes or the extension worker restarts with no incognito window open. They are never written to persistent local settings. Opening the popup compares the current hostname against keywords on-device without storing or sending it.
- **Assistance and translation caches (session-only by default)**: successful short word/phrase help, passage translations and bilingual page translations are held in browser session storage and expire when the browser session ends; incognito pages neither read nor write these caches. Keys hash the term/text, context, task level and provider/model rather than storing source URLs or plaintext inputs. **Values include model-generated hints, Chinese explanations or translations and may reflect sensitive content; hashes are not a guarantee of anonymity.** Bilingual page results also have a five-minute, at most 256-entry background memory cache.
- **Optional cross-session cache (off by default)**: only after you turn it on under “Data & Privacy” are those successful results written to local extension storage. At most 500 word/phrase entries and 1,500 combined passage/page translations are retained for up to 30 days from writing; expired entries do not hit and are pruned on access or write. Turning the setting off, using the separate clear-cache control, or clearing all reading data removes persistent entries; turning it off also clears session entries. Existing unconsented local caches from older versions are removed at startup.
- **Usage and monthly budget**: before bilingual page translation, the extension estimates tokens from pending characters and the service/model’s 30-day tokens-per-character ratio (falling back to four characters per token). It compares the estimate plus recorded monthly usage against the monthly token budget you set under Model Services (zero means unlimited). Exceeding the budget requires another confirmation in the popup or focused reader. Only counts, not source text, are used for these estimates.
- **PDF reader**: the extension does not persist the PDF address or document text in settings or diagnostics. The address appears as the current extension tab's `src` URL parameter; the browser may still keep its own browsing history. Parsed text stays in page memory. Assistance and translation results follow the session-cache rules above; incognito sessions neither read nor write them.
For every PDF page translation, only blocks not yet translated are estimated again; if recorded monthly usage plus this estimate exceeds the budget, another confirmation is required before sending that page. The reader limits downloads to 64 MiB, documents to 500 pages, and each rendered page to 16 million device pixels; larger files can use the native viewer instead.

### 2.4 ChatGPT subscription connector and official OAuth

The ChatGPT channel uses the official open-source Sign in with ChatGPT (SIWC) OAuth flow for eligible Plus/Pro accounts and requires your explicit permission to use your plan. During sign-in, the host starts a temporary loopback callback listener and opens OpenAI’s authorization page in your browser; the host validates the callback and exchanges and refreshes credentials. Sign-in and inference contact OpenAI directly, without a RelyLess relay server or an installed/running Codex CLI.

The host sends an OAuth Bearer token directly to OpenAI’s Responses API. The current HTTP preview requires `store:false` and `stream:true`; the host consumes SSE until an explicit completion event before accepting a result. It does not use a persistent remote `conversation` or `previous_response_id`; the required history is resent in each request’s `input`. `store:false` does not mean OpenAI processes or retains no data: account, security, usage, and content handling remain subject to OpenAI’s own terms. This SIWC flow does not support audio/video input, Files uploads, or transcription; RelyLess uses text assistance.

### 2.5 Grok compatibility device-code OAuth and direct subscription proxy

Grok uses device-code OAuth at `auth.x.ai`: the host requests and polls authorization, while the browser receives only a trusted verification URL, a short user code, and sanitized account/model status. The device code, access/refresh tokens, and full identity credentials never return to the browser. The host checks required granted scopes and establishes account identity through official userinfo. When an ID token is returned, the host first verifies its OIDC ES256 signature, issuer, audience, subject, and expiry, then checks that its subject matches userinfo. This channel reuses the public OAuth client ID shipped by the official Grok CLI; it is not a RelyLess-owned registration or a guarantee of official approval or third-party support. RelyLess identifies itself truthfully. The proxy header `X-XAI-Token-Auth: xai-grok-cli` denotes the compatible credential scheme, not imper…

Sign-in and account identity queries contact xAI authorization services (`/oauth2/userinfo`). Model catalog queries and inference go directly to `https://cli-chat-proxy.grok.com/v1`, with inference using `/responses`, without a RelyLess relay server or an installed/running Grok CLI. Request text is not written to prompt files. xAI receives the necessary text, account authentication, and normal request metadata. `store:false` does not mean zero retention or guarantee that the provider does not record account, security, usage, or content data; normal retention and deletion follow its own policies. Proxy entitlements, subscription tier, models, and quota may reject requests. This change adds no automatic API-key spending fallback, inference retries, or Grok multi-turn follow-up.

Migration from the old CLI channel requires reinstalling the Native host and completing fresh device-code authorization. Subsequent host updates preserve valid direct-channel authorization. Old Grok CLI credentials are not imported; old installation data is neither read nor deleted. The ChatGPT SIWC channel is unchanged. Existing Google configuration and the Antigravity CLI channel are not migrated or deleted by this Grok update. The [official Antigravity FAQ](https://antigravity.google/docs/faq/) warns that third-party access violates its terms and may result in account suspension or termination; preserving configuration does not mean official permission for this use.

## 3. Features That Require Explicit Opt-in

The following are off by default and run only after you explicitly enable them:

- **Reading history**: requires explicit enabling and adding allowed websites; disabling collection does not automatically delete existing records. Incognito pages are not collected.
- **Reading summaries**: built on top of reading history, require separate enabling.
- **Remote personalization analysis**: built on top of reading history, require separate enabling.

- **Cross-session assistance and translation cache**: requires its own opt-in under “Data & Privacy”; personal vocabulary or reading-history settings do not authorize it. Turning it off deletes existing cached results.
- **Documentation-site icon hints**: off by default; when enabled, the extension locally checks the hostname of each page you open against your keyword segments to show a hint on the extension icon. URLs are never stored or sent; only the origins of sites you choose to dismiss are saved in local settings, and dismissals in incognito windows stay in session memory only.
## 4. Data Categories

The Extension may process the following categories of data:

- **Website content**: words, sentences, body samples, titles, sections, and context used for AI assistance, sent to your configured provider.
- **Authentication information**: API keys you enter are stored in local extension storage; ChatGPT and Grok OAuth credentials are held only by the Native host to authenticate to OpenAI and xAI respectively.
- **User activity**: optional reading history and analysis processing reading, queries, and activity evidence within the scope you allow.

## 5. Retention and Deletion

- You can export or clear on-device data under the Extension's "Data & Privacy."
- Model usage statistics can be cleared separately in settings or with “Clear all reading data.” If local storage deletion fails, the operation reports failure and retains the records so you can retry.
- Delete explicit follow-up records by conversation under “Reading history → Conversations.” Clearing extension reading data does not sign you out of ChatGPT or remove host credentials. Subscription-panel sign-out clears the current account authorization in the shared record and the stale account authorization captured for this sign-out. The host ID and non-token registration information may remain for reuse on a later sign-in. The host attempts to revoke each distinct refresh grant captured from memory and disk, even when grants share a client registration. Unconfirmed remote revocation is reported honestly; if needed, revoke the app’s access in ChatGPT settings.
- Signing out in the Grok subscription panel clears local account tokens and attempts token revocation at xAI. Remote revocation failure is reported honestly and does not prevent local sign-out. If needed, revoke further access through the provider’s account controls. Clearing extension reading data does not sign you out of Grok or delete old CLI data.
- Incognito windows do not persist the question/answer records or usage statistics above, but can still use the locally authorized account for inference. Bounded host-memory conversations follow their own lifecycle, and OpenAI, xAI, or your other selected provider still receives the content required to answer the request.
- We do not retain your reading content on any server we operate.
- Data already sent to third-party model providers is subject to their own retention and deletion policies, outside our control.
- Manage diagnostics separately under “Domain detection → Runtime diagnostics”: disabling “Record development diagnostics” stops new extension records without deleting existing ones and saves the desired disabled setting for host synchronization. A connected host stops logging in its current process before attempting to persist that setting. A persistence failure reports a sanitized storage error, and the extension reports unconfirmed synchronization rather than success. The host may still load its older enabled setting after a restart; the next connection retries the extension’s saved setting. Stopping the current process’s logging is not a guarantee of durable opt-out.
- “Clear diagnostics” first removes extension logs, then requests deletion of both log files from every currently connected host. The pending-clear flag is removed only after all those hosts explicitly acknowledge success. Any host failure reports an incomplete operation and retains the request, even if other hosts have already cleared their files. With no host connected, the request also remains for retry on the next connection; diagnostics settings or cleanup never silently start a host. Other independent hosts not involved in the connection are outside this deletion scope. Errors contain no private filesystem paths or tokens. Export saves a local JSON file only when you explicitly select it. Clearing reading data or signing out does not clear diagnostics.
