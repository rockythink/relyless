# RelyLess Design System

本文件是扩展界面的唯一设计规范。`extension/design.js` 是设计 token 的唯一代码源；页面 CSS 和 Shadow DOM 组件只消费 token，不复制色值、字号或主题分支。

### 品牌标识

- 产品名称统一为 **RelyLess**，保留大小写，不在名称前附加旧中文品牌。品牌标志为独立绘制的几何 R：主体保留完整识别，左下方一小段蓝色下划线表示适量辅助，不使用翻译双字母、星芒或能力等级图案。
- 矢量母版为 `extension/icons/relyless.svg`。固定使用深灰 `#202124`、近白 `#F1F3F4` 与蓝色 `#8AB4F8`；这是品牌图像本身的颜色，不构成第二套界面主题。标志保持正方形比例，不拉伸或添加阴影、渐变。
- `icon-16.png`、`icon-32.png`、`icon-48.png`、`icon-128.png` 用于 Chrome/Edge 工具栏与扩展管理；另提供 256px、512px 输出。设置页和弹窗使用 28px SVG，邻接产品名称时图片为装饰性空 alt；页面 favicon 使用 32px PNG。
- 网页交互复用同一 SVG 母版，Logo 为 16px，邻接品牌文字使用 13px `--type-support`：词语卡显示「RelyLess · 词语释义」，其它选中内容显示「RelyLess · 内容释义」；结构卡显示「RelyLess · 阅读解构」。划选翻译操作条显示 Logo + RelyLess，相邻译文在可折叠标题中标识来源，不写入译文正文。
- 加载、错误和已认识反馈只加小 Logo；单独出现时提供 RelyLess 替代文本，已有品牌文字时图标对辅助技术隐藏，避免重复朗读。品牌不设链接、不单独接收焦点，不新增常驻入口；原词标记、顶部词注和结构下划线不加 Logo。
- 划选操作条使用共享实色 surface；相邻译文标题的品牌文字继承译文字色，兼容网页主题与系统主题不一致的情况。品牌不修改宿主排版或模型调用逻辑。
- Manifest 仅将 `icons/relyless.svg` 作为网页可访问资源，并启用动态 URL；不开放其它扩展资源，不复制 SVG 路径、不加载外部品牌资源。验收须确认真实扩展在严格图片 CSP 下仍能加载 Logo，浅深色与 320px 下不溢出，翻译折叠、关闭和已认识撤销仍可用。
- 更名更新界面、右键菜单、连接器展示名称与下载文件名前缀。扩展所在目录、Native Messaging 主机名、协议标识、既有存储键与 `Shisui Translate` 本机数据目录保持不变，避免改变扩展身份或丢失既有登录、阅读数据。

## 1. 消费机制

### 扩展页面

`popup.html` 与 `options.html` 在页面样式之前同步加载设计脚本：

```html
<script src="../design.js" data-shisui-page></script>
<link rel="stylesheet" href="ui.css">
```

`data-shisui-page` 使脚本把 token 注入页面 `:root`。`ui.css` 不定义 token，也不维护独立的明暗主题。

### Shadow DOM 与网页正文

扩展页面和注入网页的 Shadow DOM 位于不同文档。操作卡片和原文稿不以宿主网页作为界面主题来源；它们必须把共享 token CSS 放在自身 `<style>` 的第一段。正文标记、短注和相邻段落译文则按第 11 节继承网页排版。

```js
const tokens = globalThis.ShisuiDesign.cssFor(':host');
shadowRoot.innerHTML = `<style>${tokens}/* component styles */</style>`;
```

- 不提供常驻悬浮入口；网页词语与当前字幕使用 `extension/content.js` 中的局部帮助卡和 `cssFor(':host')`。选段翻译使用邻近按钮及相邻可折叠译文，不复用词语卡。
- 正文标注与相邻译文不是 Shadow DOM；`cssFor(...)` 仅作用于扩展拥有的原词、短注、词注容器、选段按钮、`emergency-translation` 与 `passage-translation`。禁止注入或修改宿主页 `:root`。原词与短注是相邻元素，不互相套用背景色；默认继承原文颜色和字体，辅助文字不小于 13px。选段按钮复用共享 surface、accent、字号、间距与圆角，不另设色板。
- 专注阅读是弹窗的本页短操作，不是常驻悬浮入口。正文通过同文档手动 popover 承载，使用共享 token 的实色表面与字体；工具栏顶部先提供退出、域名与快照说明、需单独确认的「翻译本页」和「返回原文」，再提供字号 18–24px、栏宽 60–84ch、行距 1.6–2、自动/浅色/深色主题。翻译进度提示位于工具栏下方，避免遮挡按钮。样式限制在扩展 host 内，正文元素复位宿主强制的 display/position/visibility 布局；窄屏换行，不改网页根样式。焦点进入退出按钮、Tab 留在视图内、Escape 退出后回原焦点。正文可用查词键主动求助；解释卡、词注与选段操作仍属于当前表面。正文中的「我已认识」徽标用 13px 语义色 pill 紧贴目标词起点上方（约 2px 间隙），必须以局部高优先级规则抵御宿主的 article button 样式，不压住后续正文。导航链接主动翻译只在原标签旁添加文字，不打开帮助卡或浮层。自动提示失败使用短时、非阻断状态，详情保留原始错误，不将“阅读尚未完成”作为泛化结论。
- 视频英文原文稿和当前句帮助卡使用 `cssFor(selector, theme)`，其中 `theme` 为 `auto`（默认）、`light` 或 `dark`；不另建色板，也不改变网页帮助卡或播放器原生 CC 的主题。网页内字幕组件使用 closed Shadow DOM。

禁止在组件中复制 token 数值作为 fallback；缺失设计脚本应在开发检查中暴露，而不是形成第二套主题。

## 2. 色彩

界面以中性表面为底，在 Chrome 风格的设置/侧面板布局中用实色区分功能与操作，不做品牌展示页。浅色为中性灰背景 `#f8f9fa` 与白色表面 `#ffffff`；深色为 `#202124` 背景与 `#292a2d` 表面。蓝色强调当前页、词头与主要操作，青绿色用于解构与释义，紫色区分网站自动化与语言切换；其余精确值只以 `design.js` 为准。保留扩展自身名称，不使用 Chrome 官方标志或暗示这是浏览器内置功能。

- 基础表面：`--canvas`、`--paper`、`--surface`、`--surface-subtle`、`--surface-hover`。
- 文字：`--ink`、`--muted-strong`、`--muted`。
- 分隔：`--line`、`--line-dark`。
- 交互：`--accent`、`--accent-hover`、`--accent-soft`、`--accent-line`。普通操作按钮使用实色浅蓝/深蓝灰底与蓝色边框，悬停强化边框和文字，按下切为深蓝底白字；收起、关闭保持中性。弹窗仅在主操作与已开启状态使用蓝色强调，查词词头区与句译入口仍使用蓝色功能底，不改变宿主正文。
- 主要操作与选中导航：`--action`、`--action-hover`、`--on-action`。主按钮、当前侧栏项和选中分区页签在浅色主题使用蓝底白字，深色主题使用浅蓝底深字（`--on-action` 随主题切换）以保证与深色表面的轮廓对比；禁用使用 `--action-disabled` / `--on-action-disabled`，悬停不恢复活跃色，保持 opacity 为 1。
- 理解辅助：`--teal`、`--teal-soft`、`--teal-line`、`--teal-hover`、`--on-teal`。弹窗阅读解构只在标题和已开启轨道使用青绿；释义区采用青绿底与细边；「我已认识」用实心青绿按钮和独立前景色。颜色不表示掌握程度、成功或已连接，不改变正文句法成分的语义配色。
- 持久规则与语言切换：`--violet`、`--violet-soft`、`--violet-line`。弹窗网站自动开启仅在已开启轨道使用紫色，查词语言切换用紫色按钮。所有新增色面使用完整不透明色值，不用 alpha、渐变或毛玻璃。
- 成功：`--green`、`--green-soft`、`--green-line`。绿色仅表示成功/已连接，不再作为品牌底色。
- 警告：`--warning`、`--warning-soft` 使用黄色系，只表达需要注意的状态；普通说明使用中性表面。
- 危险：`--danger`、`--danger-soft` 只用于失败、删除和不可逆操作。

所有承载文字的页面、popup、卡片、dialog、drawer、输入框和菜单表面必须解析为不透明实色。禁止 `backdrop-filter`、玻璃质感、半透明 surface 和 opacity 淡入。页面右上角的任务状态也使用实色紧凑表面；定位 host 不拦截点击，仅可见状态条及主动展开的详情接收交互。

阴影不属于 surface，可以使用带 alpha 的颜色，因为它不承载文字且不混合面板内容。透明的全屏 Shadow host、定位层、隐藏原生表单控件、无底关闭/装饰按钮也是布局例外。模态 backdrop 可使用纯遮罩透明度表示页面被阻断，但不得 blur；不能把全屏 popover host 涂成不透明色遮挡网页。

## 3. 字体

默认字体使用 `--sans`：Apple / Windows 系统 sans，并包含苹方、冬青黑体和微软雅黑中文回退。只有代码与命令可使用共享 `--mono` 等宽字体，字号仍不得低于辅助文字标准。

| 语义 | token | 字号 / 行高 | 消费点 |
| --- | --- | --- | --- |
| 页面标题 | `--type-page-title` | 22px / `--leading-title` | 设置页标题，常规字重 |
| 区块标题 | `--type-section-title` | 18px / `--leading-title` | 设置页工具栏标题 |
| 求助词头 | `--type-word-head` | 20px / `--leading-title` | 局部帮助卡目标文本 |
| 正文 | `--type-body` | 15px / `--leading-body`（1.6） | 说明、原文、英文提示、主动请求的中文说明、主要列表信息 |
| 控件 | `--type-control` | 14px / `--leading-control`（1.4） | 按钮、输入、选择、导航、选项标签 |
| 辅助 | `--type-support` | 13px / `--leading-support`（1.5） | 状态、帮助、来源、日期、标签、注释；可见文字下限 |

字重仅使用 `--weight-regular`、`--weight-medium`、`--weight-semibold`。不写 550、620、650、700、720 等插值字重。

禁止为塞入固定空间把文字降到 9–12px。空间不足时依次采用换行、增加 `min-height`、减少布局列数或省略非必要装饰。承载文字的控件不得用固定 `height` 截字。

## 4. 间距

采用 4px 基线：

- `--space-1` 4px：图标与紧凑标签内部间隔。
- `--space-2` 8px：同组控件和紧凑按钮间隔。
- `--space-3` 12px：字段、列表项和紧凑卡片间隔。
- `--space-4` 16px：标准控件内边距、popup 区块。
- `--space-5` 20px：标准卡片内边距与区块间距。
- `--space-6` 24px：内容组分隔。
- `--space-8` 32px：页面区块分隔。
- `--space-12` 48px：页面边距和大区块收尾。

新增组件不得自行引入 14px、18px、21px 等临近值来制造第二套节奏。1–3px 边框、图标几何、浏览器原生控件补偿和排版微调不属于间距 token。

## 5. 圆角与阴影

- `--radius-control` 8px：输入、选择器和紧凑状态说明。
- `--radius-panel` 12px：设置分组、帮助卡、视频原文稿。
- `--radius-pill` 999px：操作按钮、导航选中背景和开关轨道；状态文字不加装饰胶囊。
- `--shadow-low`：仅确实需要轻微浮起的表面；设置分组和原文稿不加阴影。
- `--shadow-high`：浮于网页上的局部帮助卡，使用短而柔和的阴影。

圆形图标、阅读标记的 em 圆角与 1–2px 边框属于几何细节，不强行套用组件圆角 token。

## 6. 状态与交互

- 默认、hover、active、focus、disabled 必须有可辨别的实色或边框变化。
- focus 使用共享 `--focus-ring` 与 `--focus-offset`，不能只依赖颜色极轻的阴影。
- disabled 使用 `--action-disabled` / `--on-action-disabled` 或实色 surface/文字组合；禁止降低整个控件 `opacity`。
- 成功、警告、错误使用各自语义 token；不得只靠颜色传达关键状态，必须保留文字或图标含义。
- 动效只能辅助状态变化；遵守 `prefers-reduced-motion`，减少动态效果时不启动分区 view transition，也不播放其新旧视图动画；不得用透明淡入掩盖界面加载。
- 设置采用分组导航与任务单页，不把阅读行为、显示样式、网站授权放在一条长页面中。导航分为阅读体验（阅读偏好、显示与解构、网站规则）、我的阅读（阅读记录、提示偏好）、系统（模型服务、数据与隐私、高级与诊断、使用说明）。高级页按领域识别、固定术语、运行诊断切换；普通切换回到页首并更新标题焦点；搜索命中具体设置时则打开所属子视图和折叠区域，将焦点与视口移到该设置。
- 使用说明沿用 `#guide` 主分区，按“读到哪里卡住 → 怎么操作 → 看见什么 → 如何继续读”的场景组织，不以术语表或状态机开篇。注释与阅读解构是常显的两条主线，分别配词义与句子主干的固定示例；词注、标记、待确认、渐退等概念融入实际使用场景。减少提示、局部翻译、工作资料隐私及精确机制使用原生 details/summary 按需展开。示例不调用模型；查词键复用 `data-lookup-key` 同步，不硬编码用户当前按键。相关设置使用现有分区链接，支持键盘操作、深链重载和浏览器返回。
- 常用二选一使用紧凑的原生单选框选项，桌面并列、窄屏堆叠，不缩小文字。子视图复用 section-tabs，支持方向键、Home/End、选中状态和关联面板；隐藏的统计页签不参与键盘切换。详细机制按需展开，费用、权限及删除风险紧邻实际操作。
- 弹窗顶部为品牌与设置入口。支持的网页按域名与本页状态/主操作、阅读解构、本页双语翻译、网站长期自动开启排序；底部保留查词快捷键。正常状态一屏完成常用操作，服务错误、真实错误及显式翻译确认展开时允许纵向滚动；不压缩字号。暂停本页不改变网站长期规则，服务错误保留修复入口。
- 不支持的浏览器内部页、扩展页和非 HTTP(S) 页只显示单一空状态及使用说明入口，不渲染禁用操作、服务警告或读取页面专属设置；正常页面的次级操作采用中性实色分隔行，仅主操作与已开启状态带语义强调。快捷键使用实色键帽，不扩大弹窗固有宽度。
- 查词卡片的 closed Shadow DOM 必须同步消费共享色彩 token：蓝色词头区、青绿释义区、蓝色句译入口、紫色语言切换、实心青绿「我已认识」及中性「收起」。释义失败改用危险色；禁用不降低 opacity。分区增加内边距后，320px 下长词自然换行，朗读按钮不被挤出，操作允许换行，详细句译在卡片内滚动。
- “服务 → 刷新账户与模型”必须断开旧 native 进程并建立新连接，再读取模型；安装覆盖文件后不能继续向旧进程查询状态冒充刷新。并发刷新合并，旧连接在途请求明确中断，迟到消息不得覆盖新连接。连接或模型刷新失败时保留具体错误，不显示成功提示。
- 服务错误区分输出 schema、请求参数、模型、登录、额度及上游不可用；显示安全的错误类别、调用阶段和 RPC/HTTP 代码，不回显可能包含原文、网址或凭据的上游错误正文。参数或 schema 错误不得统一建议“稍后重试”，也不得把 `max_output_tokens` 等参数名误判为登录失效。
- 原生 Structured Outputs 使用对象根节点，将帮助结果放入 `result` 字段；连接器校验并解包后，扩展收到的仍是既有局部帮助合同。上下文不足仍返回空提示且不含义项，不因此扩大结果或数据记录范围。
- API 按服务商使用 Chat Completions、Responses、Anthropic Messages、Gemini、Bedrock Converse、Cohere v2、Ollama 或 Replicate 原生协议，不统一伪装成 Chat Completions。使用相应结构化输出参数，或在协议支持的 system/prompt 中传入同一 JSON Schema，并限制输出 token。JSON 模式不能代替本地字段、义项及原文范围校验，不补默认字段或忽略多余字段。帮助 API 与订阅共用对象根节点的 result 外壳，严格校验外壳只有 result，再解包为既有局部帮助对象；流式预览同样识别该外壳。SSE 协议根据实际 Content-Type 识别流式响应；请求 stream 后收到合法 JSON 仍正常解析，不因此追加请求。
- Chat Completions 与 Responses 按实际服务端点、协议、服务商、模型及凭据隔离检测 JSON Schema 能力；不根据模型名或 /models 列表猜测。首次请求先发送不含网页正文、阅读记录或个性化信息的最小公开探测：随机枚举值只出现在 response_format / text.format 中，不放进提示词；返回必须恰好满足该枚举与字段集合。成功后业务请求优先使用 json_schema + strict:true；服务明确拒绝该格式，或成功返回的 JSON 未遵守探测约束，才使用 json_object。HTTP 200 本身不能证明支持；最小探测通过也不保证该服务支持业务 schema 的全部关键词或内容正确，仍执行原有本地校验。
- 探测结果仅在当前 worker 内存保存 1 小时，最多 64 个服务组合；缓存键为含凭据身份的 SHA-256，不保存明文 Key、正文或探测响应。worker 重启、到期或更换服务组合后重新判断，首次探测可能产生一次小额模型调用。并发调用共享探测，每个等待者独立取消，最后一个取消才中止探测；探测完成后重新验证当前页面与数据代次再发业务请求。未开启任何模型请求时不会后台定时探测。
- 只有探测的明确格式不支持错误允许回退；鉴权、限流、服务端、网络、超时与含糊的请求错误不降级。业务 schema 错误也不降级、不剥离约束重试。错误正文仅在公开探测的 400/422 分支内最多读取 8 KiB 作分类，不进入错误对象、诊断或持久存储。保持无思考参数、原有流式完成校验和六类生成文本字段的单次定向纠正；能力探测不重发业务正文，也不扩大纠正次数。
- 实测当前配置的 deepseek-flash Chat 接口：json_schema 探测返回 400 并指明 response_format 不可用，随后自动采用 json_object；公开固定样例的划词解释和自动提示请求均返回 200 且通过原有本地校验。相同服务的第二条业务请求复用能力结果，不再次探测。此结论只针对该端点与模型组合，不推断其它 DeepSeek 协议或供应商实现。严格 json_schema 成功、静默忽略、错误分类、缓存隔离及并发取消另由本地回归覆盖。
- 接口依据：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[DeepSeek Responses](https://api-docs.deepseek.com/guides/responses_api/)。Chat response_format.json_schema 与 Responses text.format 使用各自原生字段层级，不擅自切换协议或地址。

- 阅读记录拆为记录、统计、记录设置。首次未启用且无数据时不铺空图表；关闭采集后仍可查看已有档案。统计周期同时作用于记录与统计，记录设置中不显示无关筛选。已认识词独立于历史采集和个性化分析。
- 数据导出与清理集中于数据与隐私：词档案导出与完整记录导出分别保留；“清空阅读与个性化数据”保留词档案，“清空全部阅读数据”同时删除词档案与阅读/个性化数据。两种清理均保留服务配置、网站权限及采集开关，确认文案必须与实际后端范围一致。
- 服务未连接时先显示修复步骤，不铺无效模型控件；已有 API 默认显示已选服务和测试入口，编辑按需展开，新建时展开并聚焦服务商。偏好即时保存，服务表单显式保存。记录、规则和授权错误必须显示在当前页面，不把反馈留在隐藏的另一个分区。
- 当前发布临时隐藏视频字幕支持。`activation.js` 的 `VIDEO_SUPPORT_ENABLED` 同时控制视频自动开启、视频专用网站注册、字幕脚本注入和设置入口；旧 `automation.videoSites` 与视频样式偏好保留，但不能恢复播放器入口。YouTube 字幕桥在关闭期间拒绝启动，不改变原生 CC。设置中的视频页签、网站开关和使用说明均隐藏，键盘页签导航跳过隐藏项。下文视频内核规范仅用于保留实现的研发验收，不代表当前对外开放。

## 7. 页面与组件验收

1. 在 320px 宽逐一检查阅读偏好、显示与解构四个分类（句子结构、原词、词注、译文）、网站规则、阅读记录各子视图、提示偏好各子视图、服务、隐私和三个高级分区。页面不得产生横向滚动，导航自身的水平滚动除外。查词、样式偏好须刷新后仍存在；网站访问、阅读留存与个性化授权保持独立。
2. 工具栏 popup 必须通过真实浏览器 action 打开，禁止用普通标签页或强制设置 360px viewport 代替验收。popup 的 html 与 body 提供独立于 viewport 的 360px 固有宽度，不使用 `100vw`、`max-width: 100%` 等循环约束；折叠和展开时内容宽度都保持 360px，浏览器可另留滚动条空间。检查按钮横排、品牌名称可见、底部可滚动到达，并确认没有横向溢出。
3. 局部帮助卡和高级术语编辑使用无空格超长英文词、长域名、长中文说明验收；列表允许省略，帮助卡必须 `overflow-wrap: anywhere`，不能撑宽视口。
4. 在浅色和深色主题检查 computed style：正文至少 15px，控件至少 14px，辅助文字至少 13px；surface 为不透明颜色，面板无 blur。
5. 检查键盘 focus、系统文字放大、`prefers-reduced-motion` 和 disabled 对比度。
6. 新增页面必须在业务 CSS 前加载 `design.js`；新增 Shadow 组件必须调用 `ShisuiDesign.cssFor(selector)`，并使用最窄的扩展自有 selector。
7. 三次 Space 必须保持宿主页原生输入，不删除空格、不监听编辑内容、不发送输入翻译请求。帮助卡靠近视口边缘时保留安全边距，不缩小字号；中文按钮无需等待英文返回即可使用，迟到英文不得覆盖中文。
8. 保留的视频内核验收默认使用本地字幕夹具与无窗口浏览器，不自动打开 YouTube 等外站；联网视频测试须先取得明确许可，直播期间不得弹出测试窗口。使用 `tests/fixtures/video-subtitles.html` 的 native / custom / youtube 模式覆盖控件布局。保持原生英文 CC，不创建翻译覆盖层；原文稿展开、翻页、播放、滚动和时间戳跳转均不触发字幕模型请求。字号采用 16/20/24/28px，内容尺寸受播放器与视口约束，不覆盖原生控件。
9. 视频入口优先紧邻原生 CC；封闭的 HTML5 原生控件不可注入时，使用播放器下方相邻入口。“这句”固定当前短 cue 并打开共同帮助卡，“原文”独立展开英文稿。无英文字幕明确报告不可用；源变化使旧结果失效。关闭卡片仅恢复插件拥有的暂停/字幕改动，不覆盖用户 seek、播放、选轨或 CC 操作。
10. 自动开启设置必须区分持久网站规则与当前标签页手动暂停，暂停不得取消网站规则开关；单站排除优先于全站设置。权限请求从用户操作触发。新增设置卡片复用既有响应式断点，320px 下不得产生文档横向溢出。

## 8. 新增组件规则

1. 先选择现有语义 token，再写布局；不得为单一组件新增近似色、字号、间距或圆角。
2. 使用 `min-width: 0`、`minmax(0, 1fr)` 和合适的 `overflow-wrap` 保护狭窄布局；不要靠缩小文字解决溢出。
3. 页面级样式不得污染宿主网页；Shadow host 保持透明，实际 panel/card 使用实色 surface。
4. 只有出现跨两个以上真实组件、且现有语义无法表达时，才在 `extension/design.js` 增加 token，并同步更新本规范和消费方。

## 9. 英文支撑与数据边界

- 主 article 覆盖 main 至少一半的合格正文时优先采用 article，同时保留其前方 main 内的导语、主标题和引语；正文覆盖相同的嵌套候选优先较小容器。页眉、导航、侧栏、页脚、编辑区、隐藏内容与链接占比过高的候选不进入正文及模型文章上下文。
- 自动辅助只处理可靠正文主区的可见附近内容。历史原词标识按每个具体出现位置分配，不受同屏两个、同段一个或同义项去重限制；不嵌套重叠范围。已确认的自动展示严格遵循支持状态：hint 显示原词标记与顶部释义，mark 仅标记原词，quiet 不主动展示；不因同屏数量、同段重复、曾经展示或滚动再把 hint 降级为 mark。系统建议仍以当前视口最多两个突出目标、一段一个目标为提名预算，离屏记录不占名额。历史语境尚未确认时使用独立轮廓与待确认说明，不冒充三种已确认状态；人工主动求助不受自动提名预算限制。
- 启用后立即安装保存的阅读样式并监听正文变化，不等待领域识别或首批模型请求；正文资格与领域完成确认后才允许自动准备。已有语境缓存的查询与候选分析独立进行，缓存释义不等待候选分析或模型返回；没有当前语境结果时仍等待真实确认。正文晚加载、阅读根被替换或页签隐藏当前阅读根时重新识别正文，旧代次结果不得落入新页签；不以等待整篇加载或抓取未进入 DOM 的内容作为前提。
- SPA 导航与正文观察必须在真实内容脚本隔离世界中验收，不依赖修改隔离世界的 history.pushState／replaceState 来拦截宿主页调用。正文观察绑定稳定的 document，覆盖 body 替换；DOM 通知、视口事件与可见性恢复时检查当前 URL，切换文章后清理旧页面状态并重新识别正文。正文重建与视口扫描使用独立计时器，滚动或 IntersectionObserver 回调不得取消待执行的正文重建。
- “正在准备阅读提示”只属于当前有效请求；导航、正文重建或视口任务失效时撤销该任务的通知所有权。旧请求的完成或失败不得覆盖新任务状态；当前有效失败继续显示真实错误，不靠隐藏通知或自动重试掩盖失败。回归使用 content-adapter.html 的 Replace SPA body while scrolling：主世界改变 URL、替换 body、保留 main 后异步替换正文，并连续触发滚动；隔离世界中的辅助应接管新段落并在请求完成后结束准备状态。
- 显式英文查词不依赖英文页面检测、可靠文章容器或阅读解构。中文正文中的英文及行内 code 可用相同字母键加单击查询；缺少段落容器时仅映射 body 的直接可读文本，不拼接其下独立段落。正文单词所在句子超过 2000 字符时截取包含原词的局部上下文，保留中文并避开 UTF-16 代理对边界；正文之外只取点中词及最多约 1600 字符的同一可见文字片段，链接标签最多 200 字符，不放宽词组／选段的既有限制。代码块、输入区、编辑器仍排除；按钮等控件仅允许按住查词键点中可见文字，不执行原动作。自动辅助继续遵守英文正文门槛。
- 单词入口是按住查词字母再单击可见英文，默认 D，可在阅读辅助设置中改为 A–Z；正文、导航链接、普通链接、页眉、侧栏、页脚及有可见文字的按钮复用同一手势。普通点击、Enter/Space 与 Shift/Ctrl/Cmd/Alt 原生组合保持原样，输入区、编辑器、隐藏文字、代码块、非安全链接和扩展 UI 不进入显式查词。按住时仅给鼠标下的原词轻量轮廓，松键、失焦、隐藏、暂停、导航或设置刷新即解除模式。命中的左键手势在定位和服务请求前同步接管 pointerdown/pointerup/click；即使提前松键、定位失败或服务失败也不执行链接跳转或按钮动作，点击完成后才发起求助。正文有效求助可按显示偏好给原词底纹、解释卡或顶部释义；正文之外只显示解释卡，不修改网页原词或控件。自动扫描继续严格限制在可靠正文区域。
- 扩展不预设浏览器命令组合；只保留可自行绑定的本页开启／暂停命令。选段翻译、干净复制、本页双语翻译使用原有可见入口，避免 Option/Alt+Shift 与系统输入法、浏览器及网页热键争用。可选的标记键盘导航仍默认关闭。
- 导航链接查词沿用普通查词键加单击，只解释点中的词；卡片里显式「翻译整个导航文字」及链接右键菜单共用现有译文浮层。整条翻译仅验证当前可见导航链接、目标 URL 和英文文字（最多 200 字符），不替换原文、不阻断普通点击、不扩大自动扫描。过期链接或非导航链接不发整条翻译请求；关闭页面辅助后移除浮层。
- `lookupDisplay` 提供 `card`（默认）与 `annotation` 两种正文查词呈现；导航、侧栏和控件文字始终使用卡片，不在交互控件上插入短注。正文顶部释义沿用现有字母键加单击，不创建隐藏卡片，也不抢普通链接点击；仅当前语境已确认的 brief 结果进入顶部短注。重复点击同一在途词语合并，卡片模式保留同一目标的卡片节点；切换词语后只允许最新查询回写，旧词迟到的结果不得新增短注或提交成功记录。同一页面当前词语的已确认释义直接复用；来源、正文、设置代次失效后不插入迟到释义。选段与字幕维持原有交互。
- 查词按键或点击手势仍按住时，以及最后一次交互后的 180ms 内，暂停解构新批次、结构重绘、自动标注分配与异步释义回写；已返回结果等待空闲后重新校验，不因等待重新请求模型。重建请求合并后恢复，失焦、隐藏、暂停、关闭与卸载解除等待并遵守原有失效代次。正文变更以排除扩展 UI 的原文快照比较，插件自身拆分文本节点、包裹原词、添加短注不触发正文重建；宿主页实际改动原词（包括标记内部）仍使旧结果失效。
- 展示按目标原文失效，而不是按任意页面 DOM 变动失效。局部正文刷新使用独立内容代次，保留原文与定位仍有效的自动标记、主动词注、解释卡片及生成中／已完成的段落译文；保留原有节点、折叠状态和已确认内容。离屏只停止可见性计时，不移除标记、短注或已处理状态，滚回无需重新准备。普通外部点击只收起卡片；控件、导航与扩展 UI 的文字更新不作为正文变化。目标原文被修改或移除时只撤销其相关展示；页面导航、设置／授权变化、暂停和关闭仍完整失效。解构批次逐句检查原文，无关句子变化不取消有效结果；字幕卡片使用字幕组件自己的来源校验，不依赖正文视口刷新代次。
- 稳定性验收使用 `tests/fixtures/content-adapter.html` 的动态更新、原文变化、控件文字更新和双页签切换按钮，并结合离屏段落做往返滚动。确认无关更新不替换有效节点、不重置译文折叠状态，离屏返回不增加已完成内容的提示请求，目标原文变化和关闭后迟到结果不重新落地。使用延迟响应分别挂起领域、候选分析与模型，检查样式先安装、缓存先展示，首批尚未完成时新增正文及第二页签仍能接管。模拟服务只验证 DOM 与调度行为，不代表真实模型耗时。
- 原词顶部短注只给该表达在当前句子和已提供上下文中最贴切的一个释义：英文 hint 与中文 translation 指向同一义项，各使用一个自然、简短的表达，不罗列字典义项、同义词或分号／斜杠分隔的备选译法；语境说明另放卡片“当前语境”。习语与术语优先采用本句实际含义，证据不足不强造新义。主动求助与自动预备共用此规则，政策版本升级使旧释义缓存失效，但不删除词档案；未经本句确认的旧参考只可标明来源留在卡片，不得贴回原词或当作本句成功提交。
- 自动预备在提示词和 JSON Schema 中明确各字段的语言：hint、sense、meaning.en 为英文且不含汉字；translation、meaning.zh、sentenceTranslation 为简体中文且含汉字。语言 pattern 与本地现有字符范围一致；保留原有字数、长度、首尾空白和 token 定位检查。共享的双语详情 schema 遵守同一语言契约。JSON 模式不保证执行 schema，最终仍由本地严格校验。
- 对上述六类生成文本字段的失败，每个原始服务批次至多增加一次定向纠正请求，可能增加模型费用与等待时间；只重发失败条目，不重发已验证条目或不合格响应正文。固定原目标 token 焦点，不允许用 null、删条目或改目标位置规避纠正；第二次仍无效就明确报错，不发第三次请求。数量、ID、字段结构、目标范围及网络错误不进入纠正流程。
- API 与订阅由后台共用一个纠正调度器。连接器只返回已验证结果与限定的失败字段／焦点元数据，扩展再验证跨进程边界；不把不合格正文传回。有效结果保留于本次请求，全部通过后才缓存和交付。每次请求前与最终缓存前重新检查活跃页面和数据代次；暂停、导航、仅按需切换或清理后不再发纠正请求，已发出的迟到结果不能落入缓存。

- 完整的已验证预备解释随标记快照立即显示，同时用原有准备上下文读取后台结果并提交求助；命中不再推理。没有本句预备结果时，先显示明确标为“未经本句语境判定”的本地/保存参考义，再请求 brief 本句短释义；参考义不得代替当前语境。API 与订阅流只更新当前 detail 允许的字段，保留折叠状态，并标为“正在生成，暂未完成”；只有该层级最终结果通过校验并展示后才确认。full 只在显式展开时请求，不二次提交记录。截断、无效或过期结果不得提交，失败保留参考内容；显式重试绕过缓存。预备缓存按政策版本、领域、文章与原句隔离，仅使用 chrome.storage.session，保留 7 天/512 项上限且浏览器会话结束即丢弃；升级时移除旧的本地预备缓存，文章上下文不进入持久历史。
- 显式即时求助不等待新的领域分类：沿用手动设置、站点规则或已有领域缓存，缺失时使用已授权的领域倾向，否则使用 general；明确的当前内容判断优先于倾向。后台自动分析仍可识别领域。即时请求与其他任务遵守统一关闭 thinking 的规则，不额外打开工具。
- 订阅增量仅消费当前请求的 agentMessage，按原生请求、thread、turn、item 隔离；不订阅推理正文，不传递原始 JSON 片段。词语进度通过 SS_ASSIST_PROGRESS 发送所请求 detail 内已闭合且校验通过的字段。段落翻译使用 translationProgress → SS_TRANSLATION_PROGRESS，只接受已知且不重复的段落 ID，译文允许安全的未闭合字符串前缀，不泄露半个转义或代理对。进度不结束请求、不写成功记录，也不提前替换已确认词注。最终结构无效、请求失败或语境过期时撤掉未确认内容并保留旧参考；切词、切语言、取消、导航和连接更新后，迟到进度不得覆盖当前视图。
- 即时 ASSIST 可直接复用同一服务、政策、页面来源、文章指纹、领域、原句与表达的已验证预备结果，并按当前语言取值；不把异句参考义或另一篇文章中的同句解释当成本句成功。文章指纹沿用现有预备上下文，不在点击路径复制全文。brief/full 分别参与缓存与在途身份；完整结果可按严格相同语境投影为简释，不反向复用，相同实际请求共用一次推理，并向最新有效请求重放已生成的可读字段及后续增量；同页已登记的并发请求仍在读取缓存时，保留已完成的共享推理，直到请求处理结束再释放，避免最新请求加入前重复推理。仍仅在所请求层级的完整结果显示后提交，旧请求不能提交，详情展开不产生第二次求助。显式重试绕过结果缓存与共享推理；服务、政策及数据代次变化维持原有失效保护。
- 原生即时请求把模型查询与独立临时线程创建并行，仍在开始生成前确认模型存在，思考强度固定关闭。精简即时提示词并将短释义字段置于输出顺序前方；brief/full 各有严格结果结构，保留安全边界与无工具约束，不复用跨请求的模型上下文。命中与无缓存耗时分别验收，不能用缓存命中掩盖首次模型等待。
- 选段／本段与本页双语翻译复用逐项缓存与 in-flight 实现，但 page/passage scope 严格隔离。身份包含 origin、完整服务配置、翻译偏好、提示词版本和逐字原文（含空白）；page 另含 sourceHash 与标准化 context，ID/token 不参与语义键。后台内存缓存最多 256 项、5 分钟，worker 结束即清空；不混入自动预备句译。重复/重叠请求映射各自 ID 与 DOM，选段发起方保留流式进度，page 仅展示最终逐项校验结果。缓存命中仍校验页面、授权、权限与代次；失败及无有效消费者的结果不缓存。
- 阅读解构按完整原句、协议版本和完整服务配置缓存，最多 512 项、24 小时，保存到 storage.session；重复句子和并发请求共享一次推理。缓存持久化失败不影响已验证结果返回，清空后迟到的启动快照不得复活。订阅连接状态变化仍保守清空恢复的缓存；浏览器会话结束后不保留。
- 相同页面内容的领域分类可跨标签页合并在途任务；共享身份包含分类与服务代次，调用方分别验证自己的文档、页面及手动领域。服务／账号切换、权限撤回和隐私清理沿用既有失效边界，不为缓存绕过授权。
- 后台模型队列维持最多 2 个运行任务、16 个等待任务。自动支持、阅读解构、领域识别及段落翻译在出队前重新验证当前消费者；切页、关闭标签、暂停、关闭解构或设置变化时主动剔除已失效的等待任务，不等待前面的模型请求结束。一个页面退出不取消其他有效页面仍需要的共享推理；每个调用方独立校验结果，自动支持的后续子批次也重新检查有效消费者。
- 已失效等待任务记为 STALE／已取消，已知标签页或文档消失在浏览器接口边界归类；未识别的浏览器接口异常仍是错误。队列满属于 NOT_READY，不增加自动重试，不延长 25 秒 API 超时。此规则不承诺撤回已发送到服务端的请求，已发请求仍按原有超时和晚到结果隔离规则处理。
- 冷启动不要求水平测评，也不生成 CEFR 或掌握分数。预备候选区分主动查询、模型建议、领域词和词频；真实主动查询优先，覆盖可靠词形变化、短语及页面中的原始字符位置。历史词再遇须为新文章/原句重新准备，不复制旧句的具体含义；未确认义项不得预先更新学习状态。
- 自动提名综合通用词频、本地查询推断的词汇支持边界，以及当前领域特殊义／专业短语。个人因素按证据置信度参与加权，贡献不超过词频与个人混合分的 35%；这是待实际使用校准的启发式，不是准确的认识概率、词汇量或 CEFR 等级。模型仍负责结合当前句子决定是否提示；提名不代表用户一定不懂。
- 本地估计只用近 90 天当前领域及 general 的主动单词查询，按 30 天半衰期降低旧记录权重，general 跨领域证据再降权。至少 3 个、最多最近 60 个不同词形族才参与推断；重复点击、帮助次数和同词不同词形不能扩大样本量。只有查询意图、尚无成功帮助的词证据更弱。按查询词对数词频的加权低四分位估计支持边界，分布越分散，个人判断越平缓。其他领域、短语、被动曝光与“已认识”记录不参与水平推断，最后曝光时间不冒充查询时间。估计不另行保存，不新增模型调用；关闭记忆后不使用这部分历史。
- 同批句子按已解析领域复用词汇索引与个人支持边界，整批使用同一时间快照；跨批重新计算，不用长期缓存跳过用户明确偏好变化或时间衰减。仅消费配置的后台入口不读取词库；状态修改只提交变化的顶层存储项，词条原地修改显式标记，不为修改显示设置重写整个词库。
- 明确“已认识”先排除；已批准优先词、真实主动求助和自定义词优先于系统提名。普通候选的加权分参与每句前三候选的截断排序，而非仅调整显示顺序；常见词的领域特殊义与专业短语仍可进入语境判定，句首大写不一概当作专名。少量或矛盾证据保持保守，不把一次查询等同于不会，也不把未查询当作已掌握。
- 模型仅接收当前领域及 general 的近期真实查询词和明确减少辅助的词，各最多 12 项；被动曝光、单纯模型建议、其他领域记录以及单义项的减少辅助偏好不得冒充通用能力。关闭记忆时两组证据为空；证据变化参与预备缓存键。hint、mark、quiet 是可逆辅助强度，不代表学会或掌握。
- 新档案使用 `wordSchemaVersion:5`、`productSchemaVersion:1`，保存主动求助时间、义项的中英文参考义和可逆支持记录；版本 4 保留已有支持历史升级，更早的旧阅读数据进入只读归档，不把曝光转换为掌握程度。正常导出包含归档，不包含服务凭据。未来版本拒写，迁移或配额失败保留数据并允许无记忆帮助；已有预备解释不依赖词档案即可显示。
- 主动求助记录意图；只有成功展示并提交的帮助才增加词档案的帮助次数。即时页面高亮独立于该提交，失败时仍保留以便重试，暂停/导航时清除。再次出现沿用可逆支持策略；自动结果仅更新同一原文位置的标记，不能因选中其他词而删除历史标识，不允许嵌套词语标记。
- 主动查询统一接管原词已有标记或创建新标记。有效结果须更新当前出现位置的顶部短注，并更新仍打开的帮助卡；顶部语言跟随这次求助。不保留旧自动释义冒充新响应，也不把短注铺到页面上该词的每一次出现。后台个人目标合并与关闭卡片后的预备刷新不得移除或覆盖本次手动标注。原句上下文与 DOM 定位范围分别保存；预备结果的再次查询继续复用预备协议，不新增模型请求。
- 收起词语卡只关闭展示，不丢弃仍有效的最新词语查询。完整结果通过校验后，原词仍在当前页面可见、原句未变且手动标记仍存在时，补上该位置的词注，再提交成功记录；不重新弹出卡片，也不把流式半成品当作最终词注。新词语查询、切换语言、重试、导航或失效原文仍淘汰旧请求；不新增多个并行词语查询的提交机制。关闭后的失败保留原词标记和已有确认词注，不伪造成功。
- 关闭记忆后不使用或更新历史支持策略；清空另需显式操作，保留服务和站点授权，并使在途请求失效。长期词档案不保存原句、标题、来源 URL 或文章解释。
- 阅读历史清空与全部记忆清空都先持久化版本化清理标记，暂停数据访问及记忆写入，再使旧请求失效并清理相关存储。失败保留标记，允许重试，后台重启先恢复清理再开放数据入口；不等待已发送的模型请求结束，迟到结果不得回填会话缓存。历史清空保留词档案和明确词汇偏好；全部记忆清空另删词档案与旧归档。二者都保留服务凭据、设置、站点权限及采集开关。
- “仅在需要时”停止自动分析、预取、标记与被动记录，但保留字母键加单击的单词求助和句子/短段选区求助；本页已开启阅读解构时仍不自动扫描句子，只在选中单句并点击“解构所选”后请求该句结构。无预备缓存不能阻断显式求助；暂停本页关闭普通页内帮助，不改变持久站点规则。
- UI 不显示掌握率、毕业判断或学习分数。退场是可逆的支撑策略，工程验收不证明理解提升或无插件阅读能力；真实效果须另做配对内容任务评估。

### 默认退场算法与页面显示门槛

- `reading.js` 的默认策略按词条、领域、义项计算，不是科学记忆测量，也不是按出现第几次推断掌握。下面的默认流程不覆盖用户手动锁定或已批准的有界个性化调整。
- 第一次成功求助将该义项恢复为 `hint`：原词标记加顶部短注。原词默认使用轻底纹，具体装饰服从用户的原词样式；`mark` 只保留原词标记，`quiet` 不绘制自动标记或短注。
- `hint` 累计 3 个有效机会日后转为 `mark`；随后累计 3 个仅标记机会日后，进入 7 天暂隐。暂隐到期返回 `mark`；若上轮暂隐期间至少有 2 个有效机会日，后续暂隐逐级延长到 14、28 天，否则不升级。不存在自动永久消失或毕业状态。
- 有效机会要求已确认义项、前台实际可见至少 2 秒、展示阶段与应有阶段一致；同一 UTC 日最多一次，当天主动查询所在页面不计退场机会。后台候选、未显示的短注及单纯刷新不累计。阶段更新不要求立刻移除当前已显示的提示，后续分配才使用新阶段。
- 超过 14 天没有有效机会，默认恢复 `hint`；再次主动求助也会重置该义项的退场进度。手动“少提示这个用法”不自动过期，直到再次求助或恢复自适应；锁定的手动选择优先。
- “我已认识”是独立的词级自动提示排除：顶部词注悬停或键盘聚焦显示操作，指针移出后保留约 500 毫秒并可经按钮周围的隐形热区直接移入，单词卡也提供主操作。只在用户明确操作后保存 knownAt；跨页面、领域和可靠屈折词形生效，不扩展到衍生词、子串或歧义词干。自动候选、预备历史词、缓存与迟到结果都受此规则约束；主动查词仍可用且不会清除排除。
- 保存成功立即撤下目标词已有的自动词注和手动词注，收起该词的解释卡片，并阻止操作时在途的该词解释重新插入词注；以后仍可主动查词。提供 8 秒撤销；失败保留原注并显示错误。“提示偏好 → 已认识词”可随时恢复，不要求开启历史采集。词汇偏好通过独立的 `SS_WORD_PREFERENCE` 消息同步同词及可靠词形的标识，不触发 `SS_REFRESH`、全页重建、服务代次失效或缓存清理；无关词的自动标注、手动词注、段落译文和在途请求保持有效。撤销仅重新扫描受影响的正文块，其他节点保持原位。恢复同步影响已打开页面和同词的跨领域记录；显式已认识不增加主动查询次数，也不等于掌握该词所有义项。
- 刷新页先按当前领域与 general 中的已查询词做本地匹配，覆盖可见正文的有效句子，不受模型选取的六个可见句名额限制；本地请求按原协议分批，模型选句数与输入上限不变，文章上下文继续组合标题、导语、视口段落及其邻文。缺少本句、本出现位置的预备结果时只显示未判定义项的原词标记，不复制旧句解释，也不借用同句另一位置的义项；模型失败不应抹掉本地标记。已确认处于 quiet 或手动锁定暂隐的用法不绘制自动标记；未判定新语境仍是独立的中性历史标识，不推断旧义项适用。记忆关闭、仅按需模式、未启用网站、非可读或不可见范围及原词设为纯文本，仍可能导致肉眼看不到历史标记，不能解释为用户已经学会。
- 同一词的重复出现分别使用该位置当前语境的确认结果，不按第二、第三次出现分配固定显示等级；当次主动求助仍只更新所查询的位置，不把其解释复制到其他语境。
- 行内提示可切换为“回忆遮罩”：提示文本以模糊遮罩呈现，鼠标悬停或键盘聚焦可视觉还原；键盘与读屏用户可聚焦提示并按回车／空格显式揭示内容。遮罩是纯显示层，不改变学习状态，也不产生额外的求助信号；减少动态效果时取消过渡。
- 帮助卡片展示该词的求助历史（第几次求助、上次距今）；历史来自既有词档案字段，不新增采集内容。词或用法重复求助后，卡片页脚可建议“固定译法”，点击经一次性暂存键跳转到术语设置并预填，绝不自动创建术语。
- 本地领域识别置信不足时保留最佳候选领域；只在设置页主动运行“领域测试”后展示候选，并引导读者通过现有网站规则手动选择。阅读页面不出现领域浮动入口，也不根据候选自动改变领域。

### 速度与真实阅读效果验收

- 速度验收分别测量直接 API 与原生订阅，使用相同输入并区分首个内容增量、首个可读词义／译文及完整结果耗时。first_content 是首个接受的非空文本增量，不代表已经形成可读结果；受控服务只验证提前展示与状态边界，不能作为真实模型速度数据。单次真实请求不代表平均值或稳定性能，不因接入流式而承诺总生成时间下降。
- 三阶段与 3／3／7–14–28 参数保持为可撤销的默认策略，不视为已验证的记忆规律。后续真实读者评估比较“历史轻标记＋按需释义”和“三阶段渐退”，尽量匹配词汇难度、原有熟悉程度与阅读材料；检查当下理解、阅读耗时、打断与标记密度，并在例如一周后用无提示的新语境检验词义回忆或理解。学习效果改善不能仅以查询次数下降、标记曝光或工程测试通过判定；这类跨天结果不由开发验收代替。

## 10. 本页双语翻译

- 工具栏原生 popup 在阅读解构之后、站点自动开启之前提供独立区域，不再藏在“更多”。开始和继续均明确确认：保留英文，只处理读到附近的正文，原文、标题、章节及有限相邻文本发送给所选服务并按其规则计费；停止不能撤回已发送请求。
- Alt+Shift+T 只打开真实 action popup 并聚焦确认或现有状态，不直接开始；Alt+Shift+S 不变。一次性 intent 绑定 tabId、完整 URL 和 30 秒有效期，原子消费，导航/关页清理。浏览器不支持或拒绝 openPopup 时清 intent 并提示点击工具栏，不提高 Chrome 116 最低版本。
- 可信扩展页依次执行 PAGE_UI_INJECT、EMERGENCY_BEGIN、SS_EMERGENCY_START，并重新核对 URL；resume 必须显式传布尔值。令牌保存在 storage.session，绑定页面、支持数据代次与服务指纹。导航、根替换、服务/相关设置变化或结束会话使旧授权失效，不能转移到新页。继续使用新 token 恢复同页未完成单元。
- 源单元是同一父节点中的连续文字/行内元素片段，遇子块切开递归；保留 br 换行、链接、强调与行内代码文字。译文仅使用自有 span/textContent 插在原父元素内，表格在各 td/th 内，Grid/Flex 在各卡片内，不增加外层布局项目。直接裸文本布局无法安全插入时报告 skipped:layout；排除导航、输入、编辑区、代码块、隐藏内容、视频和非 HTML 目标。
- 原文节点与监听器保持身份，不保存 innerHTML 快照。源文或语境变化立即撤掉旧译文，并按版本在派发和提交前复核；清除只移除扩展插入物，保留站点新增内容。停止后继续监听源变化，但绝不发请求。
- IntersectionObserver 上下各预取 600px，当前视口优先，再按距离/文档顺序；远端为 deferred。单页一个未完成批次，ready 最多 16 项；每批最多四项、源文合计最多 4000 字符，长单元无损分块并独占批次，不拆代理对。隐藏页不派发，滚动只重排下一批；DOM 变更约 120ms 合并，复核受影响来源和邻文，忽略自有插入。
- 每项 context 为闭合的 title/heading/before/after：160/160/400/400 字符，标题在会话开始固定，邻文限同根同章节，表格优先相关表头。源文加上下文每批最多 12000 字符，两端校验。上下文只消歧，不并入译文、不执行指令；不额外生成摘要或领域请求。
- 全文内部返回完整覆盖输入 ID 的 items/errors。已知 ID 的坏项或缺项只标该项失败；未知/重复 ID、坏 JSON 或顶层结构损坏使本批全部失败，不猜测配对，后续批次可继续。只缓存验证通过的项。失败处显示“本段未译完”和局部重试，popup 支持重试失败段落；只发失败/未完成块，不自动重试。401/429、权限、连接和超时等请求错误停止派发，保留已有译文和待办，继续须再确认。
- 单元状态为 deferred/queued/translating/complete/failed/skipped，长单元全部块成功才完成，已成功块按原索引保留。SS_STATUS.emergency 使用 off/translating/waiting/complete/partial/stopped/error；completed/failed/pending/skipped 互斥且合计等于 total。popup 显示“已译 X / 已识别 Y 段”，附近处理完不冒充整页完成。停止保留可恢复状态，包括尚无译文的会话；返回英文清空状态、断开监听并恢复原辅助/解构。
- token 内 requestSeq 单调递增，EMERGENCY_CANCEL_REQUEST 将 cancelledThrough 串行提升并剔除队列；取消先于请求注册也有效。源文/语境失效只取消该批消费者，旧调用 settle 后释放页面槽；停止/导航撤销 token。继续沿用后台两个执行槽/16 个等待任务；共享推理保留其他有效消费者，无消费者的迟到结果不落地、不缓存。不新增活动 fetch/native turn 的定向取消或断开整个 port。
- 本模式暂停自动分析、被动阅读机会和有效阅读计时，不新增全文阅读事件、个人词档案或持久正文；用户原有语言、辅助模式与网站规则不变。选段仍使用独立严格协议、流式进度及原阅读提交规则，不能因全文允许部分成功而放宽。
- API 与 ChatGPT 连接器同步使用 page/passage scope；订阅在 native parse 阶段保留逐项结果，扩展再校验。升级需同时更新扩展与连接器并重跑连接器安装，不回退旧协议；API 用户无需安装连接器。
- 验收使用隔离 Chromium profile、真实 360px action popup、loopback API 与 native fixture，不读取真实账户。覆盖原位布局/节点身份、未知/缺失/乱序结果、失败块重试、停止/恢复、25 秒超时、快捷键取消零调用、隐藏页、导航/根替换/服务切换、明暗/窄宽/125% 缩放及普通求助/选段回归。受控响应证明协议与恢复，不证明真实模型质量、供应商速度或降本倍率。

## 11. 阅读样式与网页兼容

- 设置入口为“显示与解构”。readingStyle 保存 original、annotation、translation 三层，每层仅含 style、color、size；分别控制被标注英文、顶部短注、段落译文，互不共享可变设置。旧 translation/color/size 自动迁移到三层，原词保留原比例；运行时写入只接受新结构。注解仍固定在顶部，不接受任意 CSS 或 URL；注解不改变原词的水平占位——原词宽度即天然字形宽度，词距与换行与未标注时一致。
- extension/reading-style.js 是校验、归一化、CSS 生成与标签布局的唯一实现；设置页隔离 iframe 和实际阅读页共用词注容器与生成器。顶部注解绝对定位、以原词为中心水平居中，容器只预留一行注解行高的垂直空间，左右零边距、不预留释义宽度，原词字形与字体保持不变。相邻标签在同一行碰撞时，后出现的标签上移一层（最多两层，容器补足两行留白）；仍碰撞则按与相邻标签的间隙截断省略，悬停与查词卡保留完整文字。布局在注解附加、文案更新与移除时重算，不进入滚动热路径。
- 显示与解构按句子结构、原词、词注、译文、视频切换，一次只显示一组控件与对应预览。宽窗口左侧编辑、右侧预览，容器不足 680px 时上下排列；只有该页使用宽内容区。iframe 仍与实际阅读页共用样式生成器并自适应高度；视频字号与主题使用现有 token。
- 句子结构分类始终可预览粒度与线型，不依赖网站授权、最近活动页或真实分析开关，不查询页面会话、不调用模型。语义颜色来自 ShisuiDesign.structureRoles/structureColors，与真实网页共用。全站自动解构移至网站规则；修改预览偏好不自动开启分析。
- 每层支持默认、纯文本、文字颜色、虚线、背景、边框与引用装饰，字号比例为 80/100/115/130/150%。原词只缩放被标记的英文；注解字号单独决定顶部留白并保留 13px 下限。译文 default 无边线、背景或大内边距，约 .4em 段间距，沿用来源字体/字号/颜色；明确选择的 quote/border/background 保留装饰。全文译文在源单元父元素内，以可用宽度、min-width:0/max-width:100% 布局，不写死像素宽度或逐段加品牌。选段面板继续使用原关联定位 helper（包括表外或横向 Flex 外面板），不混用全文原位插入规则；设置预览共用样式。
- 自动配色使用网页当前文字颜色及轻量底色，不强套插件浅/深色板。原词与注解继承字体，注解显式采用 .035em 字距、正常词间距与 1.45 行高，不继承宿主标题的负字距；段落译文参照对应原文块的计算字体、字号、行高比例和颜色。只修改扩展自有元素，不复制网站 class 或读取跨域样式表规则。
- 原词、短注和段落译文显式使用自身前景色作为文字填充色，隔离宿主渐变标题等宽泛选择器带来的透明填充；不修改未标记文字的渐变、颜色或字体。
- 原文块及祖先的 class/style/常见主题属性、样式表节点变化与加载、窗口尺寸、系统配色变化按渲染帧合并更新；移除译文时解除监听。纯 CSSOM/adoptedStyleSheets 等无这些通知的变更不保证自动同步，Canvas/PDF 等非正文 DOM 也不在此兼容范围内。
- 每层提供跟随网页及麦穗金、松石绿、湖蓝、雾紫、陶土红命名配色，来源仅为 ShisuiReadingStyle.palettes；按钮有键盘操作与 aria-pressed 状态，自定义色盘作为补充。纯文本或不消费强调色的默认样式选色时切换至文字颜色，避免无可见效果。自定义背景按亮度选择黑白前景；不模糊或降低原文透明度。连续修改使用独立草稿与串行保存，旧响应不得覆盖最新选择；恢复默认深拷贝全部三层。
- 样式保存通过 SS_READING_STYLE 定向更新，不广播整页重建，也不为生成样式调用模型。布局变化后新进入视口的内容仍遵循原有准备规则。所有自动顶部词注统一跟随 helpLanguage（默认中文），不区分系统推荐、历史查询词或曾经求助；选中文使用 translation，选英文使用 hint，不再对系统推荐强制英文。切换已有词注的语言复用已确认的双语结果，不为语言切换本身新增模型请求，也不替换英文原文。主动查词仍沿用当次明确选择的语言。
- 交互与预设分类参考陪读蛙 [translation-style](https://github.com/mengxi-ream/read-frog/tree/main/src/entrypoints/options/pages/translation/translation-style) 和 [decorate-translation](https://github.com/mengxi-ream/read-frog/blob/main/src/utils/host/translate/ui/decorate-translation.ts)，代码独立实现，没有复制 GPL-3.0 实现。

## 12. 多服务配置与切换

- API 服务使用 `apiServices: [{id,name,providerId,baseUrl,model,apiKey,options}]` 与 `activeApiServiceId`，最多保存 20 条连接。30 种 LLM 服务商预设与陪读蛙集合对齐，以 `extension/api-providers.mjs` 为单一来源，不包含 Google/Microsoft Translate、DeepL 等专用翻译引擎；协议代码独立实现。名称用于界面，稳定 ID 用于选择；`activeApiProvider(settings)` 只返回明确选中的服务，不猜测替代项。ChatGPT 订阅仍是独立的 `providerKind`。
- 配置顺序为服务商 → 凭据 → 模型，预填地址与适合无思考调用的默认模型，原生附加字段按服务商展示。支持读取模型目录时提供实际结果，也始终允许手动输入模型 ID；目录不可用时明确说明，不生成假的清单。模型目录读取限受信设置页、需要精确 origin 权限，且不要求先保存草稿。
- 服务商选择的当前值与每个列表项优先在名称前显示许可已核对的本地品牌 Logo；自定义协议，以及暂未取得明确图标再分发许可的 Jalapeno Cloud、Tensdaq，使用中性 API 图标，不冒充 OpenAI 品牌。图标随扩展打包，不请求第三方图标服务；来源与许可保留在 icons/providers/NOTICE.txt。选择器兼容 Chrome 116，以 Popover 列表提供图标、选中状态、键盘方向键／首尾定位／名称输入查找及取消，仍通过原有服务商字段与 change 事件更新表单，不修改凭据隔离或保存规则。
- Azure 提供原生协议模式、资源名与 API 版本；Bedrock 使用 region 与 Bearer API Key，不接受 AK/SK 或冒充 SigV4；Ollama 允许无 Key。远程地址只允许 HTTPS，HTTP 仅限 loopback，拒绝 URL 内嵌凭据、查询参数及片段。原生协议不兼容时不自动改走其他协议。
- 旧单项 `provider` 自动迁为 `legacy-api` / “原有 API 服务”，保留地址、模型和密钥；写回后删除旧字段。已存在的服务数组优先，包括有意保存的空数组，不能复活旧配置。 没有 providerId 的历史连接统一保留为 openai-compatible，不按域名猜测协议，也不覆盖原有 URL、模型或 Key。
- 新增服务不会复制其他服务的密钥；编辑同一服务时仅同服务商、同 origin 的空密钥输入可以保留旧值，切换服务商或 origin 必须重新输入。保存、切换、清除密钥和删除都不覆盖其他服务。仍被其他服务、独立领域识别或网站规则使用的权限不得删除。 取消、失败或离开未保存草稿时清理仅为该草稿授予且没有其他用途的权限。
- 删除当前服务的确认必须显示下一项服务或无服务状态；提交明确的替代 ID，最后一项删除后保持空选择，不悄悄切换至 ChatGPT。切换或修改当前模型/地址/凭据使旧请求、缓存和紧急翻译授权失效，迟到结果不得采用；只修改未选中服务不影响当前推理。
- 内容脚本的 `STATE_GET` 使用显式白名单，只返回辅助模式、记忆开关、查词交互、语言、显示样式、当前领域、视频显示和必要阅读历史状态；不返回服务列表、模型名、站点规则、自定义术语或服务凭据。嵌套显示配置同样按字段构造，新增配置不会自动暴露给页面。只有受信扩展界面可编辑完整配置；词档案导出仍不包含服务凭据。
- 本轮未扩展视频字幕模式；视频功能待单独讨论。重新加载扩展、设置页和已有阅读页后使用新的样式及服务列表。
- 本次排版与交互验收覆盖 Substack、DEV、Hashnode、Ghost、WordPress、BBC、Guardian 的真实文章 DOM，模型响应使用显式夹具，不据此宣称完成付费模型在线或翻译质量验证。Medium 匿名页受 Cloudflare 限制，会员页只检查可见预览；全文及现存的范围交叉/重复校验错误不能标为通过，不放宽校验或绕过付费墙。

## 13. 模型数据与渲染边界

- 领域分类、预备解释、主动求助及段落/整页翻译复用不可变的系统边界规则；页面标题、正文、候选、历史参考和阅读证据均以 JSON 数据提供，不拼入系统指令。带有伪造角色或“忽略指令”的原文仍按原文传递，不删除合法引用。
- 预备解释、主动求助与段落/整页翻译输出须通过对应的严格结构、字段、长度和目标校验，不接受工具调用、额外权限请求或越界字段；领域分类仅消费允许的领域值。原生任务保持只读、禁止审批及工具执行；兼容 API 不提供工具。结果以 textContent 渲染，不解释为 HTML。
- 自动化仅验证数据/权限/输出结构与渲染隔离，不能证明真实模型永远不会受提示词注入影响。真实模型的语义可靠性需要独立评估，不宣称百分之百免疫。

## 14. 本机开发诊断

- 设置增加独立“诊断”页，默认启用元数据记录，提供开关、异常概览、最近 50 条事件、JSON 导出与单独清空。查看诊断不启动连接器、不刷新账户、不调用模型；关闭不删除已有记录，清空不碰词档案、凭据或站点授权。
- 页面、后台与已连接的原生服务使用同一 UUID traceId。记录请求、服务、首段内容、输出校验及实际呈现阶段；呈现回执绑定标签页和文档，一次消费，后台重启后继续有效。失败在状态详情中保留诊断 ID，成功生成但尚无页面回执不等于已展示。
- 按请求去重错误，不把服务错误和请求错误重复计数。同类失败累计至少 3 次提示多次失败；完成请求达到 10 秒提示慢请求；150 秒未结束提示疑似中断；应呈现的成功结果 15 秒无回执提示未确认显示。统计范围仅为保留窗口，不能据此断言真实网络或模型的根因。
- 选段维持整批严格校验；全文沿用同一单条字段/长度/中文规则，以逐项错误区分部分成功和不可映射的整批失败。诊断区分结构/数量、字段、未知或重复条目、类型、空译文、首尾空白、超长及不含汉字；只留固定错误码、受限内部 ID、字段枚举、数量与长度，不保存正文或原始错误响应。
- 自动支持同样区分批次形状、数量、词项字段和编号；目标内容、字符/token 范围、焦点、英文提示、中文释义、义项、双语解释及本句翻译失败带条目序号和固定字段路径。只记录字段名，不记录字段值；API 和订阅使用共享校验器，保留原有语言/长度/范围约束，仅在所有条目最终通过后交付。可纠正文本字段遵守单次定向纠正规则，最终失败不冒充成功。
- 阅读解构的请求、服务及校验事件纳入扩展与原生诊断白名单，界面显示为“阅读解构”。目前不要求页面呈现回执，因此不据此生成“未确认显示”告警；请求完成不等于已验证页面显示。
- 白名单排除正文、完整模型响应、URL、原始异常/堆栈、原始 stderr、账户和凭据；服务 origin 与模型名只留 SHA-256 指纹。原生 stderr 仅在内存分类为固定错误码和字节数，限频后写入。日志不主动联网，不实现默认原文采集。
- 扩展使用 chrome.storage.local 的独立 diagnostics 键，最多 500 条、7 天，读写时裁剪。关闭与清空设置代次屏障，阻止旧请求迟到事件重新出现；存储失败不阻断阅读请求，并显式提示诊断可能不完整。
- 已连接的原生连接器将相同安全事件写入 data/diagnostics.jsonl，单文件 256 KiB，保留一个 .1 轮转文件；目录 0700、文件 0600，启动时清理超过 7 天的事件。开关单独保存在 diagnostics-config.json，配置损坏时停止记录，须显式重新设置。macOS 默认 data 位于 ~/Library/Application Support/Shisui Translate/data。
- 仅经现有 Native Messaging 通道镜像，不为日志主动连接账户。离线清空请求持久保留，下一次连接再清原生文件，并在界面说明等待同步。仅 API 且连接器未连接时，排障通过扩展导出的 JSON，不声称日志已落入原生文件。
- 自动提示由扩展生成；开发助手只在用户发起的工作会话中读取可访问的本机日志或导出文件，不宣称会话结束后仍持续巡检。诊断不追溯启用前的失败，也不把模拟服务验证当作真实模型可靠性证明。

## 15. 阅读记录与有界个性化

已实现独立阅读记录、客观统计与有界模型分析。本机仅保留必要查询原句、主题摘要及行为统计，不持久保存整篇正文或阅读页面 URL。保存记录、生成摘要、历史个性化和自动应用分别授权；默认全部关闭。既有“记住求助词”和站点访问权限不自动授权新增留存；还须逐一添加精确 origin 白名单。

### 信息架构与客观反馈

- 新增独立“阅读记录”入口，不塞进诊断或词汇背诵页。顶部为四张轻量指标卡：时钟图标／活跃阅读时长（估算），书页图标／浏览英文词数（估算），文本放大镜／主动查询词条，引号／查阅例句。统一单色线性图标、中性表面，不用奖杯、火焰、等级、排名、连续打卡、完成度圆环或庆祝动画。
- 默认近 30 天，可切近 7 天及累计；标注统计起始日期。图表只用同色每日柱形和明确单位，支持切换时长、词条、例句；每日按 UTC 划分，显示真实零值、无记录日期与未开启状态，不用红色惩罚空白日期，也不把“较少查询”描述为进步。
- 下方为“主动查询／自动标注／阅读摘要／提示规则”四个页签。支持词条、领域、时间和来源筛选。词条列表显示原词/短语、简短释义、查询次数、最近时间、当前内联提示深度；展开显示保存的原句、当时的解释及本句译文。相同词的不同领域/义项可展开，不把再次遇到等同于再次主动查询。每次载入 300 条，可继续加载；未载入完整范围时明确标注次数仅汇总已载入部分。导出不受列表上限限制。
- 自动标注单列，区分个人历史词再遇与系统候选，只记录实际显示的结果，后台候选/预取不进入历史。它不增加主动查询词条或例句指标；用户随后明确查询才产生主动事件。相同页面上下文的重复渲染去重。
- 当前内联深度显示“短注／仅标记原词／暂不自动提示”，按词条、领域与义项计算；展示生效原因、手动设置或自动策略来源及到期时间。主动打开帮助卡始终提供词义、语境与可展开的双语原句；卡片折叠与原文的内联深度互不混用。提供增加提示、减少提示、恢复自适应和锁定手动选择，不出现掌握率或能力等级。

### 统计口径与保存规则

- 活跃时长仅累计扩展已启用、前台且可见的英文正文阅读会话；失焦、隐藏、暂停或连续静置 60 秒后暂停，明确是估算而非眼动测量。浏览词数仅估算视口中稳定出现至少 2 秒的正文片段，单页面会话最多保留 20000 个不含原文的词位置标识，配置变化不重置会话内去重；心跳按会话和 UTC 日聚合，不把页面总词数或滚动到底作为读完。可在说明中查看计算条件。
- 主动查询分“完成查阅次数”和“不同词条数”：成功校验、实际展示并提交一次才计一次，按请求 ID 去重；失败、重试中的重复回执、缓存预取不计成功。不同词条按规范词形/短语去重，不将跨领域义项重复计为新单词；显示“含短语”，不把生成出的解释用词算入。
- 例句仅计主动词语查阅所对应的原句及主动选中的单句，按规范化原句指纹去重；同一句查询多个词不重复增加不同例句数。整段请求另记段落数量，不将多段分片或模型译文条目数冒充例句数。
- 明细使用独立 IndexedDB，不复用浏览器会话预备缓存或 500 条诊断缓冲。原句最多 1000 字符，超长原句不留存；自动标注仅保存词条、来源及实际显示深度，不保存其句子。默认保留 90 天查询例句、实际标注事件和阅读摘要；不含正文的每日累计可长期保留，并清楚区分累计与当前明细范围。单条删除须同步撤销相关当日统计和派生偏好；整体清空涵盖明细、汇总、主题摘要、手动提示规则、个性化版本与相关缓存；保留服务、权限及采集开关，停止后续记录须另行关闭开关。原文去重指纹使用本机私有盐，不作为全局内容标识上传。
- 历史数据库版本 2 在单个版本变更事务内为事件增加时间／ID、类型／时间／ID、领域／时间／ID 及领域／类型／时间／ID 索引，并回填去重回执；不复制原句或译文建立第二份搜索正文。普通列表按时间和 ID 倒序游标分页，仅取本页正文；加载更多追加并去重，筛选／时间范围／页签或数据修改重置游标。仅统计查询不读取事件正文；精确子串搜索及其总数仍需扫描筛选范围内的保留事件。
- 超过 90 天的逐次贡献合并到 UTC 日归档，保留数值累计和加盐词条／例句指纹集合；跨日、归档与近期记录之间求并集，不能直接相加每日去重数。保留最小事件 ID 回执防止过期事件重放重复计数，因此存储不是固定容量。单条撤销只适用于尚保留的明细；明细过期后只能整体清空相关累计，不能宣称仍可按旧 ID 精确撤销。清空同一事务删除事件、贡献、回执、归档和个性化控制数据。
- 摘要写入在同一个数据库事务中检查预期历史修订号；清空、删除或更正历史发生在模型返回与提交之间时，拒绝写入，不依靠写完后再删除补救。原句指纹仅用于本机去重，不等同于不可逆匿名化。
- 无痕、输入区及排除网站不采集；站点访问授权不等于历史留存授权。仅按需模式停止被动扫描与记录；自动模式的本机统计需独立显式开启。摘要每页面会话最多一次，活跃阅读至少 15 秒后发送不超过 2000 字符的临时样本，不持久保存样本。摘要最多 1000 字符，标明模型生成，可更正和删除；更正后移除模型生成标记，失败显示未生成，不伪造摘要。
- 现有 words 可提供有限词条聚合、最近求助与支持状态。它们不能补齐逐次查询、精确浏览词数、完整例句或全文阅读历史；旧数据单独标记历史导入，新增指标从启用时开始，缺失显示未统计而非零。

### 有边界的主动个性化

- “提示偏好”分为分析偏好、已认识词和调整记录。关闭分析时只显示必要说明；开启后先显示当前状态与下一步，分析时间及有效策略收在详情中，保留恢复默认和版本撤销。开启后，首次须有至少 3 个含查询或摘要的会话，或 10 次主动查询。自动分析含失败至多每 7 天尝试一次，手动分析间隔至少 60 秒；资格不足不占用请求次数，相同依据不循环分析。限制输入摘要、请求次数与输出大小，说明会调用所选 LLM、可能产生费用；浏览器关闭时不宣称继续运行。
- 提示偏好明确区分授权未开启、证据不足、等待确认与已应用，在详情中展示当前密度、提示深度及优先词；打开开关不冒充已经生成并应用了偏好。不自动替用户开启阅读留存、origin 白名单或模型授权。
- 个性化分析未开启、证据不足、无新证据、冷却期内，以及摘要未授权或已生成，均使用显式 NOT_READY；设置／历史代次变化导致结果失效使用 STALE。诊断将这些预期状态记录为已取消而非未知故障；保留原错误提示、资格阈值和冷却时间，真实模型及存储异常不得被吞掉。
- 输入仅取授权保留的近 30 天最多 40 条查询/摘要依据、客观活动统计和最多 40 条手动提示规则；不附页面 URL 或整篇文章。自动标注次数只描述系统输出，不能自我证明用户不懂或已掌握。LLM 个性化提案不得生成心理、健康、政治倾向等用户画像，亦不输出英语能力等级；本地候选算法可依上文规则使用带置信度的查询难度估计，两者不混同。
- 自动标记调整只影响候选优先级、允许范围内的内联提示深度与密度；用户主动重查可恢复提示，未查询不能单独作为减少提示的证据。保留每屏提示硬上限、仅按需模式与手动锁定；自动调整可撤销，30 天到期，不修改查询历史。模型不能自动选择 quiet；降低密度或深度须引用真实主动查询，优先词也须来自所引用的查询。 优先词在候选截断前参与排序；已应用的 depth 对普通系统建议同样生效，不再只绑定优先历史词。明确的词级“已认识”排除优先，只有撤销或恢复自动提示才解除。
- 领域调整采用独立偏好层，仅在当前内容判断不足时作为倾向；用户手选领域、手工站点规则及明确的当前内容证据优先。模型不得生成或修改站点规则，不覆盖原有规则，也不因为最近常读某领域便给所有页面同一分类。
- 翻译提示词不开放给模型任意改写。模型仅返回严格白名单的个性化配置，如解释简洁程度、术语一致性及上下文侧重点；由程序拼成独立数据层。核心系统指令、权限、目标语言、brief/full 分级输出结构与校验不可变，来源内容始终作为不可信数据。
- 流程为“有限证据快照 → 模型提案 → 严格结构和证据引用校验 → 风险分类 → 生效或等待确认”。仅候选优先词变化可在另行允许自动应用后生效；任何密度、深度、领域或翻译偏好变化均须确认。无效/超时/证据不足保持现有规则，不能覆盖为随机默认。
- 每次调整保存前后值、时间、证据记录 ID、策略版本、适用范围和撤销入口。删除历史或更正摘要会废止依据派生的旧版本，不能靠回滚恢复；关闭个性化或修改手动规则同样推进数据代次，使在途旧提案失效；回滚/生效同步失效相关预备缓存，不让旧结果继续使用旧规则。关闭阻止后续请求，已发送请求不能承诺撤回或免计费。

### 实现与验收

实现分为 history-store.js（独立存储与统计）、history-service.js（权限、实际回执与失效）、personalization.mjs（有界模型协议）及 ui/history.js。API 和原生订阅服务共用严格 schema 与固定指令；不修改视频功能。

数据结构版本（wordSchemaVersion:5、productSchemaVersion:1、历史 IndexedDB:2）、历史修订号／授权 epoch／支持数据代次、模型协议及策略版本分别负责迁移、拒绝过期读写、解释派生规则，不能互相代用。

本轮验收：240 项检查通过；五千词隔离后台场景中，读取页面配置及修改解释语言均不读取／重写词库。真实 Chromium IndexedDB 的 1005 条样本中，近 7 天纯统计读取 305 条范围内贡献、零事件正文；列表从 300 条游标追加到 305 条，筛选重置为首屏。过期归档、归档与近期精确去重、重放拒绝和清空均实跑；后台测试覆盖清理失败、工作线程重启恢复，以及授权检查与摘要提交之间的清空竞态。这些数字不代表真实用户数据库延迟或模型调用速度。

验收覆盖重复回执、统计去重、保留与删除、迁移边界、手动规则优先、越权提案、相同证据不强化、失败频率、撤销授权与迟到结果。隔离 Chrome 配合本地模拟模型实际验证阅读采集、重复查询、自动标注、选段只计数、摘要更正、提案应用/回滚、翻译偏好、按需模式不后台推理、导出和清空。桌面与 320px 均做实际视觉检查，窄屏无页面横向溢出；304 条独立存储实验验证列表扩展与完整导出。上述验证不代表真实模型输出质量或真实服务费用已经实测。
