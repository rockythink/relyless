# ADR 0003：域名关键词网站提示

- 状态：proposed
- 日期：2026-09-25
- 参与讨论：Issue #37
- 取代：无
- 被取代：无

## 背景

用户常在文档类站点阅读英文技术内容，希望这些网站更容易开启阅读辅助。现有主机匹配 pattern 只能表达「协议 + 主机」的完整授权，无法表达「域名中包含 docs 一类片段」；为发现这类网站而申请全部网站权限则范围过大。

## 决策驱动因素

- 不新增浏览器权限、不自动启用任何网站。
- 检查网页域名属于浏览轨迹观察，是既有隐私边界之外的新行为，必须默认关闭并如实告知。
- 匹配结果只用于提示，授权仍走现有逐站点权限路径。

## 备选方案

### 全部网站自动辅助

申请所有 HTTP/HTTPS 主机权限后可在任意站点直接开启，但权限范围远超「提示文档类网站」的需要，且绕过逐站点授权意图。

### 仅弹窗内提示

打开弹窗时才提示，无需监听导航，但用户不点图标就永远看不到提示，解决不了发现性问题。

### 内容脚本通配注册

按内容脚本匹配主机关键词需要过宽的主机权限且随页面注入运行代码，成本高且不可按域名片段精确判定。

### declarativeContent

浏览器侧规则匹配、扩展不接触网址；评估中，见 Issue #37。

## 决策

设置形状为 `automation.keywordHints = {badge:false, keywords:[...], dismissed:[]}`。弹窗提示始终生效：打开弹窗时扩展经 activeTab 已有当前标签页网址，只在本机内存中把 hostname 按 `.`/`-` 切分段与关键词做整段相等比较，不观察导航、不保存、不发送网址。图标徽标是唯一需要观察导航的部分，因此默认关闭、由用户开启（`badge`）：开启后仅用 `webNavigation.onCommitted` 观察主框架 http/https 提交，命中仅在对应标签页的扩展图标显示紫色「+」徽标与提示标题，并在 `chrome.storage.session` 记录一个按标签页的非持久标记以便及时清除；徽标关闭时后台直接读取存储判断、不解析网址。弹窗中显示说明并仍通过现有「此网站以后自动开启」申请该 origin 权限；「不再提示此网站」把该 origin 记入本机设置的 dismissed 列表。关键词可编辑（2–32 位小写字母或数字，至少含一个字母，最多 20 个）。命中规则、开启全部网站、忽略或授权该站点后提示消失。

## 结果

### 正面影响

文档类网站可达且授权动作保持原有最小权限粒度；无权限、无网址持久化、无远程传输。

### 代价与风险

开启图标提示后扩展确实在观察每次主框架导航的域名——这是用户明确选择的例外，已在设置说明、设计系统与隐私文档中写明；关键词误配（如过宽词）可能在不相关站点提示，由用户编辑列表控制。

## 实施与验证

`activation.js` 提供匹配与校验，`background.js` 监听提交并管理徽标/会话标记，弹窗与设置页提供图标提示开关、关键词、忽略列表；单元与后台夹具测试覆盖匹配、闸门与徽标生命周期，`npm run check` 通过。
