# ADR 0009：任务反馈归属于操作表面

- 状态：accepted
- 日期：2026-10-04
- 参与讨论：[Issue #54](https://github.com/rockythink/relyless/issues/54)，仓库所有者确认采用
- 取代：无
- 被取代：无

## 背景

网页右上角固定任务组件在忙碌时缩为圆圈，隐藏文字、详情和关闭按钮；其可见表面仍接收指针事件。后台准备因此占用了与当前操作无关的网页位置。复现中，原生按钮被遮挡时点击没有到达；撤下组件后相同位置可点击。

## 决策驱动因素

- 保留英文与阅读节奏，不让后台任务成为常驻网页入口。
- 真实失败必须可解释、可重试，不能以撤下全局组件为由吞掉错误。
- 不增加权限、模型请求、持久阅读数据或远程处理。
- 内容脚本、原生 popup 和 service worker 的文档生命周期不同，旧状态不能迁移到新页。

## 备选方案

### 保留可关闭的右上角任务条

能够改善忙碌圆圈的可解释性，但仍占据宿主页面位置；组件的显隐、关闭和任务所有权形成第二套全局界面。

### 反馈归属于当前操作表面

自动准备与解构状态在 popup 查看，主动求助与局部翻译在原处反馈，扩展自有阅读器使用自己的工具栏。代价是后台错误需要工具栏徽标提醒。

## 决策

采用第二方案，删除全局任务层及关闭状态，不保留旧接口别名。内容脚本按七个固定键保留有界任务文字、忙碌和错误状态，经 `SS_STATUS.tasks` 提供给 popup；popup 只在可见时读取，不启动自动工作。明确指定期限的临时提示按期移除；模型失败不设置自动到期，保留到重试、关闭或生命周期失效。

错误聚合使用 `PAGE_TASK_STATUS {error, sequence, pageUrl}`。后台校验原生扩展 sender、主框架、文档 ID 与当前完整 URL，并在异步操作后重新核对。SPA 后原生 sender.url 可能仍为首次注入地址，仅核对同源；当前 URL 必须匹配标签页与主框架。文档内序号递增，SPA 导航保留水位但清错误，并通知内容脚本；重复通知重报当前状态，不重复失效表面。跨文档提交及关页清元数据。会话存储只保存文档 ID、序号、错误布尔值，不保存 URL 或任务文字。

任务错误与已有右键错误分别管理；任一错误显示 `!`，优先于网站提示 `+`。解决一个错误不能抹掉另一个。用户暂停、导航或切换阅读表面时清理旧反馈，迟到结果不能重新挂载旧界面。

## 结果

### 正面影响

普通网页没有固定任务圈或全局状态条；显式操作仍有加载、失败与重试反馈。状态只在现有表面呈现，不扩大权限、采集或模型费用。

### 代价与风险

后台失败依赖可见的浏览器工具栏徽标，具体文字需要打开 popup 查看。浏览器暂停内容脚本或拒绝消息时不能保证即时同步；导航与文档校验必须防止旧徽标复活。

## 实施与验证

迁移所有任务调用与复制子模块；专注阅读新增独立状态文本，不覆盖翻译确认；删除旧悬浮 Escape 规则及实现转发断言。自动回归覆盖消息信任、徽标优先级、序号、导航异步竞态以及局部反馈失效。真实 Chromium 扩展验证 popup、局部服务未连接错误、浅深页面点击、专注阅读工具栏、导航与暂停清理；状态夹具不代表真实模型调用或翻译质量。
