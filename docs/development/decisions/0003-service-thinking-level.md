# ADR 0003：模型服务提供可选思考档位

- 状态：proposed
- 日期：2026-09-24
- 参与讨论：dapao-777，见 [Issue #26](https://github.com/rockythink/relyless/issues/26)
- 取代：无
- 被取代：无

## 背景

既有策略把全部模型任务统一关闭 thinking：按服务商与模型启发式下发关闭参数，已识别的强制推理模型在请求前拒绝。启发式随新模型发布需要人工维护；恒思考或需要推理才能完成的模型（如 StepFun step-3.x/5、OpenAI o 系）因此不可用，用户只能换服务。

## 备选方案

保持纯启发式可以维持最小的请求面，但不可用模型列表会持续变长且语义不可见。全局档位会让用户在一次配置中改变所有服务的计费与延迟特征，风险集中。为每家服务商写专有控件则重复造轮子，违背单一 provider 字段约定。

## 决策

在 provider `fields` 机制上新增 per-service「思考模式」枚举：自动（默认，行为与现状一致）、关闭、低、中、高。传输层按档位把启发式改为显式参数：自动与关闭沿用既有关闭约定并对恒思考模型请求前拒绝；低/中/高按服务商原生参数（reasoning_effort、thinking.type、reasoning.effort、enable_thinking、thinkingConfig.thinkingBudget、Ollama think）开启推理并跳过恒思考拒绝；Gemini 档位统一映射为官方动态预算 thinkingBudget: -1。档位并入结构化输出能力探测身份，探测请求携带相同参数。无思考参数通道的协议（Replicate、Jev 判定）不展示该选项。订阅连接器不受此选项影响，固定关闭。

## 结果与风险

开启推理提高单次请求延迟与计费，由用户在服务上显式选择，用量统计与月度预算照常覆盖；显式档位（低/中/高）的请求超时从默认 180s 放宽到 300s，避免强推理被 TIMEOUT 误杀。档位语义依赖服务商实现，不支持的字段仍以明确报错呈现，不删除参数重试、不回退默认强度。低/中/高在 enable_thinking、thinking.type 等布尔通道上粒度相同；Gemini 由动态预算接管。旧版本扩展保存的未知选项键在服务归一化时会被拒绝，降级使用该扩展需重新保存该服务。

## 验证

`npm run check`；传输层测试覆盖各协议档位映射、关闭语义的通用参数补发与恒思考拒绝；归一化测试覆盖选项合法性与无该字段协议的拒绝。设置页字段与持久化在真实浏览器验证。
