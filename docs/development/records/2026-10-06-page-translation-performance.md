- 日期：2026-10-06

## 背景

用户实测反馈陪读蛙的全文翻译速度与效果更好。本次接受该观察，不重复对比产品以质疑反馈；测量并修复本扩展已存在的整轮等待、页面进度传输缺口和长段落切块上下文问题。

## 目标

- 流式服务在最终响应前即可显示有界未确认译文。
- 一个慢请求不闲置另一个已释放的槽。
- 连续长段落分块有切块处的同段前后文，要求忠实译文而非缩写摘要。
- 保持原文、用户确认、费用边界、并发上限、取消与失败诚实性。

## 非目标

不改默认英文优先方向，不扩大后台预译范围，不切换用户的服务或模型，不提高并发，不新增重试、权限、文章存储、全篇术语表或视频翻译。

## 实现边界

后台与 Native 主机复用既有翻译进度路径。内容脚本校验 session/token/requestSeq/generation、原文与上下文后显示临时纯文本片段；最终响应仍独立校验。滚动补位保留旧请求的全局在途计数；旧 runner 不得清理新 runner。失败只停止后续派发，不丢掉其他已在途批次的确认结果。

长段落的内部切块前后文来自同段相邻分块，首尾沿用邻段，各400字符以内；有效性签名仍基于原单元。Google（Antigravity）的现有 CLI 仅在最终解析后回调，不声称 token 级流式。

## 数据、权限与费用

无新增接收方、权限、模型档位或持久数据类别。原有每批最多四项、4000源字符及12000源文加上下文限制不变。预览不计入成功缓存或阅读记录。译文缓存版本1→2，旧策略的选段/本页结果不命中；已有词档案与阅读记录不变，冷缓存请求可能重新产生费用。

## 风险与回滚

预览可能最终失败或被替换，必须撤下未确认部分，不能宣称完成。同段其他确认分块要保留。停止后已经发送的请求仍可能计费。整体回滚对应运行时代码与文档；不能恢复旧策略命中来掩盖质量问题。

### 六次公开文本模型对照

经用户允许，取三段公开官方文档，各用旧/新提示词调用本会话默认模型一次，共六次；未调用用户配置的订阅账号，不发送私人网页或凭证。

- [MDN Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)：网络失败与HTTP错误、Response.ok、抛异常。
- [PostgreSQL MVCC](https://www.postgresql.org/docs/current/mvcc-intro.html)：读写互不阻塞、SSI、最严格隔离。
- [Python truth-value testing](https://docs.python.org/3/library/stdtypes.html#truth-value-testing)：__bool__/__len__ 条件及异常传播。

六个响应均通过本页结果结构与语言校验。两组提示词都保留核心条件；新Python译文把两个方法对应结果表达更清楚，PostgreSQL新译文给出完整SSI名称。MDN新译文使用「200范围」，不如旧译文「200–299」明确。因此没有证据证明新提示词整体显著优于旧提示词，更没有证据证明已超过陪读蛙。此次质量改进是切块上下文与保真要求的修复，不作模型效果保证。

### 2026-10-10 补充：全文翻译接管后台槽位

确认会话写入后复核自动任务使用者，移除失效排队项并中止已无有效使用者的自动 API 尝试。所有共享使用者都失效才中止；显式解构和其他页面仍需要的推理保留。原传输结算后释放槽位，维持用户并发上限；主动中止不会伪报 TIMEOUT、服务连接失败或触发备用服务。未新增权限、接收方、存储类别、重试或连接器协议；订阅连接器已发出的推理仍等待结束，API 中止不保证免计费。

### 2026-10-11 发布前自动审查修正

PR #60 自动审查发现三处取消路径缺口：自动解构的路由判定使用空 guard，指令白名单未覆盖判定 API；主动取消提前返回导致尝试从用量及预算中消失；provider NOT_READY 被误分类为取消，隐藏了真实服务不可用。三项行为回归在修正前全部失败。

自动请求改用明确的调用标记，解构在选路前建立完整来源与模式 guard，自动判定也受接管边界约束。STALE/CANCELLED 向调用方传播，不写判定失败路由缓存；真实判定失败仍沿用主服务回落。取消前汇总已报告或估算的用量，不计服务错误或成功答案；provider 取消仅限 STALE/CANCELLED，NOT_READY 仍记 error。保留既有汇总结构、保留期与无痕规则，双语隐私说明同步澄清。

- 完整检查：702 tests pass，0 fail，3775 assertions，48 files。
- 加载真实扩展的 Chromium 受控 HTTP 实跑：先启动自动判定，再确认全文翻译；服务端观察到旧判定连接中止，首批4单元在153毫秒出现。判定响应固定延迟3000毫秒，译文响应100毫秒，仅为合成文本与本地服务证据，不代表线上模型性能。
- 用量入口实际显示取消判定和首批翻译共2次尝试、0服务错误；取消判定保留267个估算输入 token，诊断为 STALE/cancelled，未写成功答案。新回归另覆盖恢复后重新判定、预算包含取消用量及 NOT_READY 的故障统计。

### 2026-10-11 补充：失败/聚焦及共享生命周期

复审另发现四处边界：没有模型文本的失败控制被当成译文收敛原词；词注子按钮获得键盘焦点时原标记不恢复；迟到显式用户可能加入已中止共享推理；导航 guard 的普通 Error 已可由诊断分类为 STALE，但取消环只检查 code。

样式直接根据既有译文片段结构区分真实文本与本地控制，词注 focus-within 恢复原标记，无新增状态字段。取消环使用既有诊断分类；显式解构只在有效 guard 及带类型的共享取消时允许一次新的采用，保持路由、已得结果与去重；真实认证、超时、输出错误、HTTP 故障仍返回失败。共享使用者 guard 本就将未标记来源错误规范成 staleWork，因此不扩展提供者文案匹配重试。

- 完整检查：716 tests pass，0 fail，3857 assertions，48 files。新增行为回归覆盖迟到授权、跨页导航、既已共享的显式用户、四类不得采用的服务故障、导航取消与配置/认证 guard 保留；关键接管与导航回归修正前失败。
- Chromium 真实生成 CSS 的浅/深色组件实跑：修正前失败段背景透明、Tab 到提示仍透明；修正后失败段保留底纹，已译静息段透明，Tab 到提示与已认识按钮均恢复底纹。预览插入收敛、删除恢复，确认文本继续收敛；实际截图已检查。此为样式组件实跑，不声称完整扩展错误页或全页无障碍认证。

### 2026-10-11 补充：后置路由 guard 与 CI 持久化屏障

路由判定返回后，来源 guard 的普通 Error 也必须通过既有诊断分类识别 STALE/CANCELLED；否则导航取消会被记作 judge-failed 并污染同内容路由缓存。新增消费者回归在修正前观察到新文档跳过第二次判定，修正后重新判定并成功返回解构。

- Chromium 加载真实扩展副本，通过受控 HTTP 完成旧文档判定后检查来源：提供者返回 ok，请求返回 STALE，routeDecisions 为空；新文档相同句子实际重新调用判定并返回规范化 clause。服务端调用顺序为 judge、judge、structure，无真实付费服务。
- 最新完整本地检查：717 tests pass，0 fail，3861 assertions，48 files。
- Linux CI 的两项既有登出测试失败来自“等待40毫秒即可假定磁盘已清除”的时序假设，不是本次翻译代码更改的运行时行为。测试改为在旧持久凭据实际撤销入口读取磁盘快照，同时保持迟到凭据的撤销受阻；仍严格验证本机 token 已清除、登出未提前完成及撤销失败被报告。没有修改连接器实现或放宽断言。六项相关生命周期回归本地通过；远端 CI 另行检查。
