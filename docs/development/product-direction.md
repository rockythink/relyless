# 产品方向

## 一句话承诺

RelyLess 保留真实英文，只在读者卡住时提供足够继续阅读的支撑，并在不需要时退后。

## 当前优先方向

### 1. 英文始终是主体

默认体验应帮助用户继续读原文，而不是生成另一篇中文文章。自动提示保持稀疏；中文解释、选段翻译和本页双语翻译都应由明确动作触发，并保留原文。
专注阅读是用户主动进入的本地正文快照，而非默认替换网页。它只在可靠提取时呈现，退出能回到未搬动的原页；自动辅助仍受英语阅读区域、用户启用和按需模式约束。在专注视图按查词键单击正文是独立的明确求助，不开启被动扫描。原页已有双语结果时暂停并保留，退出可继续处理。

### 2. 帮助必须与当前语境有关

词义、短语、句子结构和追问都服务于眼前文本。优先解决“这里是什么意思、为什么这样写、句子主干是什么”，而不是建立脱离语境的课程或词汇游戏。

### 3. 自动行为必须有可靠边界

只有在能可靠识别主要阅读区域和英语内容时，才允许自动扫描或提示。导航、按钮、评论区、代码、输入区和站点无关内容不应被扩大处理。选择“只在主动求助时”后，后台分析、预取、自动标记和被动记录必须真正停止。

### 4. 本地优先，但不伪装成完全离线

能在本机完成的识别、规则、状态和有限记录留在本机。必须调用模型时，界面和文档应说明发送什么、发给谁、何时发送、可能产生什么费用。需要长期保存或远程分析的能力必须由用户明确开启。

### 5. 支撑可以减少，也可以恢复

提示、标记、安静状态、“我已认识”和复习都必须可解释、可撤销或可恢复。产品不应通过不可见评分替用户宣称“已经掌握”，也不应把少求助包装成竞赛成绩。

### 6. 服务差异不应破坏核心阅读流程

API 服务、订阅连接器、本地模型和路由能力可以不同，但失败必须可理解并尽量回落。网络、额度、认证、模型格式或升级目标失败时，不能悄悄展示未确认内容。

## 明确不做

除非产品方向文档先被社区讨论并修改，否则以下内容不进入默认产品：

- 默认替换整页英文或隐藏原文；
- 自动翻译导航、控件或无法确认的页面区域；
- 打卡、连续天数、排行榜、等级、惩罚性提醒或掌握度游戏；
- 根据被动浏览推断能力、职业、身份或其他敏感画像；
- 未经明确同意长期保存整句、整页正文、页面 URL 或浏览历史；
- 为提高“功能数量”而增加常驻悬浮入口、重复设置或并行交互体系；
- 将某一家模型服务变成产品不可替换的隐性依赖。

## 评估新功能的五个问题

1. 它是否让用户更容易继续阅读真实英文？
2. 它是否只处理用户能预期的内容和范围？
3. 用户能否看懂、停止、撤销或恢复它？
4. 数据发送、保存和费用是否清楚且最小化？
5. 服务失败或能力关闭后，核心阅读是否仍然可用？

任何一项答案不明确，先写 Issue 或 ADR，不直接提交大规模实现。

## 改变产品方向

改变默认阅读体验、隐私边界、自动行为或明确非目标时：

1. 先创建讨论 Issue，写清用户问题、证据、替代方案和风险；
2. 若决定会长期约束多个模块，新增 ADR；
3. 在实现 PR 中同步更新本文件、README、设置内使用说明和相关隐私文档；
4. 用真实浏览器场景验证，而不是只依赖单元测试。
